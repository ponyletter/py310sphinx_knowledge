# GitHub 优质开源生态与参考导航

现代软件开发讲求“站在巨人的肩膀上”。构建一套兼具专业排版、高并发接口与移动端渲染的知识库小程序，离不开全球开源社区优秀项目的基石支持。本章整理并深度解析支撑本项目的核心开源技术生态。

---

## 1. 文档工程与知识引擎生态

传统的 Wiki 或 Markdown 渲染器往往缺乏全局引用、目录大纲树（TOC）和专业排版能力，Python 生态中的 **Sphinx** 是 Linux 内核、Python 官方文档和主流大型开源库的标配。

| 开源项目 | GitHub 地址 / 官网 | 在本项目中的核心作用与价值 |
| :--- | :--- | :--- |
| **Sphinx** | `sphinx-doc/sphinx` | 核心文档编译引擎，支持跨文件跳转、自动化大纲树、多语言与多主题扩展。 |
| **MyST-Parser** | `executablebooks/myst-parser` | 让 Sphinx 具备 CommonMark 与 GFM (GitHub Flavored Markdown) 的丰富语法，支持公式、警告块与属性注入。 |
| **Furo** | `pradyunsg/furo` | 极简、现代、自适应移动端的 Sphinx 主题，排版优雅，暗色模式支持极佳。 |
| **Sphinx-Book-Theme** | `executablebooks/sphinx-book-theme` | 交互式技术书籍首选主题，带有交互侧边栏与章节折叠功能。 |

---

## 2. 后端异步接口与资产服务生态

在后端技术选型上，我们摒弃了笨重复杂的传统框架，采用以轻量、极速著称的现代异步 Python 架构：

```text
       ┌──────────────────────────────────────────────┐
       │             Uvicorn (ASGI Server)            │
       └──────────────────────┬───────────────────────┘
                              │
       ┌──────────────────────▼───────────────────────┐
       │             FastAPI Web Framework            │
       └──────┬───────────────────────┬───────────────┘
              │                       │
   ┌──────────▼──────────┐ ┌──────────▼──────────┐
   │ Pydantic Validation │ │  PyJWT Authentication│
   └─────────────────────┘ └─────────────────────┘
              │                       │
   ┌──────────▼───────────────────────▼──────────┐
   │        SQLite3 (WAL Mode, Zero-Config)      │
   └─────────────────────────────────────────────┘
```

| 开源项目 | 特性与选型理由 |
| :--- | :--- |
| **FastAPI** (`tiangolo/fastapi`) | 具备现代异步 `async/await` 支持，基于 Python 类型提示，自动生成 OpenAPI / Swagger 交互文档，运行性能比肩 Node.js 与 Go。 |
| **Uvicorn** (`encode/uvicorn`) | 基于 `uvloop` 和 `httptools` 的极速 ASGI 异步服务器，配合多 Worker 模式可充分利用多核 CPU。 |
| **PyJWT** (`jpadilla/pyjwt`) | 无状态安全 Token 签发与校验，支持 HS256 / RS256 算法，避免服务端存储 Session 带来的额外内存开销。 |
| **Pydantic** (`pydantic/pydantic`) | 严格的入参类型校验与序列化，从根本上防止恶意 SQL 注入与入参异常。 |

## 3. 小程序前端富文本渲染神器：mp-html

在微信小程序中渲染技术文档的富文本，是所有开发者必须逾越的“天堑”：
- **微信原生 `<rich-text>`**：不支持复杂的 CSS 样式，代码块无行号且不换行，表格不能左右滚动，点击图片无法大图预览；
- **旧版 `wxParse`**：早已停止维护，存在严重的内存泄漏问题，且不支持现代 HTML5 语义化标签；
- **`mp-html` (`jin-yufeng/mp-html`)**：当之无愧的小程序富文本组件天花板。

### 为什么选择 `mp-html`？
1. **全功能支持**：原生支持公式渲染、代码高亮（Prism.js）、表格自适应滚动与高清晰度图片懒加载；
2. **轻量高性能**：内置 AST 语法树预解析，在渲染长篇技术文章时流畅不卡顿；
3. **安全沙箱**：自动过滤未知危险标签，防止 XSS 跨站攻击；
4. **扩展能力**：支持自定义样式注入，完美契合 Sphinx 生成的 HTML DOM 节点树。

## 4. 本章小结

技术选型的本质是**权衡（Trade-off）**。我们选定的 `Sphinx + FastAPI + SQLite + mp-html` 技术栈，兼顾了极高的开发效率、极致的服务器开销（单核 1G 内存服务器即可丝滑运行）以及极致的移动端阅读体验。从下一阶段开始，我们将正式进入微信生态的从零实操。
