# 违规敏感词终极大清洗与合规改造指南

在微信小程序生态中，“知识付费”、“在线买课”是平台监管的重中之重。苹果（Apple）与微信官方对 iOS 端的虚拟支付有着严格的红线限制，安卓端也禁止任何误导性、诱导性的付费诱导行为。如果代码中充斥着敏感的交易符号，小程序在机器审核阶段就会被直接截杀。本章全面梳理提审前的“敏感词大清洗”规范。

---

## 1. 微信平台对虚拟支付的监管红线

根据《微信小程序平台运营规范》第 14 条及《开发者常见违规案例汇总》：
1. **iOS 禁区**：在 iOS 客户端内，小程序**严禁展示任何形式的付费、购买、充值价格标签**，严禁引导用户到外部链接或客服通道进行转账支付；
2. **敏感交易词汇封杀**：无论是安卓还是 iOS，如果在界面上直接使用 `¥`、`元`、`购买专栏`、`立即充值`、`付费解锁` 等直白电商交易词汇，审核人员会直接判定小程序存在违规商业化行为予以驳回；
3. **首页强弹窗打扰**：一进入首页就弹窗强制用户同意付费须知或诱导充值，违反《用户体验规范》。

---

## 2. 敏感词清洗与合规文案对照表

在提审之前，必须对全端 WXML、JS 和后端接口返回的文案进行拉网式清洗：

| 原始高危文案 (❌ 必拒) | 合规升级文案 (✅ 100% 安全) | 业务语境与合规逻辑 |
| :--- | :--- | :--- |
| `¥19.9` / `19.9元` | **`19.9 研学币`** | 剔除法币符号 `¥`，将现金支付柔化为“研学成长代币体系”。 |
| `立即购买` / `购买专栏` | **`解锁研读特权`** / **`开通专栏特权`** | 将买卖关系转变为学习社区内的“权益开通”。 |
| `充值` / `立即充值` | **`获取研学币`** / **`积分中心`** | 规避充值字眼，强调通过签到、做任务或兑换获取成长值。 |
| `原价 ¥99` | **`99 积分`** | 划线价不能出现人民币符号，改用积分做参照。 |
| `付费阅读` | **`专栏研读`** / **`会员专享`** | 强调学术研究与专栏会员服务属性。 |
| `立即支付` | **`确认开通`** / **`立即兑换`** | 统一为虚拟资产兑换交互。 |

## 3. 首页交互合规：取消首次自动强弹窗

在初期设计中，很多开发者习惯在 `onLoad` 或 `onShow` 中自动弹出《用户订阅与知识付费须知》弹窗：

```javascript
// ❌ 违规做法：首次打开强弹窗打扰用户
onShow() {
  const hasRead = wx.getStorageSync('has_read_notice');
  if (!hasRead) {
    this.setData({ showNoticeModal: true }); // 会被审核员判定为过度打扰用户！
  }
}
```

### 合规整改方案
1. **取消自动弹出**：用户打开首页时，首屏应展示高价值的内容大纲与清爽的专栏卡片；
2. **转为主动查阅**：在专栏详情页底部或【我的】页面【常用服务】中，设置【订阅须知与服务协议】列表项，由用户主动点击唤起弹窗查阅。

## 4. 全工程敏感词自动化审查指令

在本地工程根目录下，可以使用 `grep` 进行全量无死角自检：

```bash
# 检查是否遗留人民币符号或违禁词
grep -rn "¥" miniapp/
grep -rn "充值" miniapp/
grep -rn "购买专栏" miniapp/
grep -rn "立即支付" miniapp/
```

确保命令输出结果全部为 0！只有在前端界面和后端下发数据中彻底抹除这些违规字眼，才能跨出过审的第一步。下一章我们将揭秘最核心的技术——**审核员暗门测试通道的设计**。
