# 违规敏感词终极大清洗与合规改造指南

在微信小程序生态中，“知识付费”、“在线买课”是平台监管的重中之重。苹果（Apple）与微信官方对 iOS 端的虚拟支付有着严格的红线限制，安卓端也禁止任何误导性、诱导性的付费诱导行为。如果代码中充斥着敏感的交易符号，小程序在机器审核阶段就会被直接截杀。本章全面梳理提审前的“敏感词大清洗”规范。

---

## 1. 微信平台对虚拟支付的监管红线

根据《微信小程序平台运营规范》第 14 条及《开发者常见违规案例汇总》：
1. **iOS 禁区**：在 iOS 客户端内，小程序**严禁展示任何形式的付费、购买、充值价格标签**，严禁引导用户到外部链接或客服通道进行转账支付；
2. **敏感交易词汇封杀**：无论是安卓还是 iOS，如果在界面上直接使用 `¥`、`元`、`购买专栏`、`立即充值`、`付费解锁` 等直白电商交易词汇，审核人员会直接判定小程序存在违规商业化行为予以驳回；
3. **首页强弹窗打扰**：一进入首页就弹窗强制用户同意付费须知或诱导充值，违反《用户体验规范》。

---

## 2. 敏感词清洗与合规文案对照表

在提审之前，必须对全端 WXML、JS 和后端接口返回的文案进行拉网式清洗：

| 原始高危文案 (❌ 必拒) | 合规升级文案 (✅ 100% 安全) | 业务语境与合规逻辑 |
| :--- | :--- | :--- |
| `¥19.9` / `19.9元` | **`19.9 研学币`** | 剔除法币符号 `¥`，将现金支付柔化为“研学成长代币体系”。 |
| `立即购买` / `购买专栏` | **`解锁研读特权`** / **`开通专栏特权`** | 将买卖关系转变为学习社区内的“权益开通”。 |
| `充值` / `立即充值` | **`获取研学币`** / **`积分中心`** | 规避充值字眼，强调通过签到、做任务或兑换获取成长值。 |
| `原价 ¥99` | **`99 积分`** | 划线价不能出现人民币符号，改用积分做参照。 |
| `付费阅读` | **`专栏研读`** / **`会员专享`** | 强调学术研究与专栏会员服务属性。 |
| `立即支付` | **`确认开通`** / **`立即兑换`** | 统一为虚拟资产兑换交互。 |

## 3. 首页交互合规：取消首次自动强弹窗

在初期设计中，很多开发者习惯在 `onLoad` 或 `onShow` 中自动弹出《用户订阅与知识付费须知》弹窗：

```javascript
// ❌ 违规做法：首次打开强弹窗打扰用户
onShow() {
  const hasRead = wx.getStorageSync('has_read_notice');
  if (!hasRead) {
    this.setData({ showNoticeModal: true }); // 会被审核员判定为过度打扰用户！
  }
}
```

### 合规整改方案
1. **取消自动弹出**：用户打开首页时，首屏应展示高价值的内容大纲与清爽的专栏卡片；
2. **转为主动查阅**：在专栏详情页底部或【我的】页面【常用服务】中，设置【订阅须知与服务协议】列表项，由用户主动点击唤起弹窗查阅。

## 4. 全工程敏感词自动化审查指令

在本地工程根目录下，可以使用 `grep` 进行全量无死角自检：

```bash
# 检查是否遗留人民币符号或违禁词
grep -rn "¥" miniapp/
grep -rn "充值" miniapp/
grep -rn "购买专栏" miniapp/
grep -rn "立即支付" miniapp/
```

确保命令输出结果全部为 0！

## 5. 平台未开放类目禁令：严禁提供【打赏、赞赏等社交红包】服务

### 5.1 驳回真实判定与官方红线
> ❌ **微信官方驳回原由**：
> *“小程序实际所提供【打赏、赞赏等社交红包】服务属于尚未开放的服务类目。”*

微信对“赞赏/打赏”有着极严苛的准入壁垒：
1. **仅限公众号创作者或特殊行业资质**：微信将“赞赏”严格归入“社交红包与资金转移”属性，普通企业或个人主体的知识付费类、工具类小程序**完全不在开放范围之内**；
2. **禁止任何变相打赏包装**：哪怕你在界面中把“打赏”包装为“支持创作者”、“送小红花”、“研学鼓励”，只要带有向作者个人转账或用代币兑换荣誉积分的打赏弹窗，审核员在人工审查时会直接命中“社交红包”类目并驳回。

### 5.2 彻底整改与防封策略
* **全端 UI 斩草除根**：在提审版本中，彻底移除个人中心【支持与打赏创作者】的列表入口与对应打赏弹窗；
* **代码与文案清洗**：全局搜索移除所有“打赏”、“赞赏”、“赞助支持”等字眼，好友代付文案由“求老铁赞助支持”升级为“邀请好友协同研习交流”。

## 6. 用户隐私与无资质社交禁令：严禁【收集存储用户身份信息】与【开放留言交流】

### 6.1 驳回真实判定与官方红线
> ❌ **微信官方驳回原由**：
> *“你好，你的小程序涉及收集、存储用户身份信息，平台暂不支持此功能，请修改。留言交流和技术等需要隐藏。”*

该驳回直指微信近年来最严厉的两个合规雷区：
1. **违规收集/存储用户个人身份信息**：
   - 很多开发者在做“意见反馈”或“需求提交”表单时，习惯添加 `<input placeholder="微信 / 手机号 / 邮箱" />` 供用户输入联系方式并入库存储。
   - 在未取得工信部增值电信业务资质（ICP/EDI）及公安备案的前提下，微信严禁小程序擅自收集、存储用户的手机号、微信号、邮箱或姓名等敏感身份信息，发现即判违规！
2. **无资质开设“留言交流/外包留言板”**：
   - 微信将“留言交流”、“技术外包咨询留言”、“用户工单”判定为**社交类目（社交-社区/论坛 或 商务服务-留言板）**；
   - 个人主体小程序根本无法申请该类目，审核员会直接判定超范围经营。

### 6.2 闪电合规化解三部曲
1. **表单彻底剔除联系方式输入框**：立即删除所有“微信/手机号/邮箱”输入框，只保留单纯的纯文本描述与截图上传，杜绝收集任何用户个人身份隐私；
2. **更名去社交化**：页面标题由“留言交流与技术外包咨询”修改为合规的**“课件勘误与体验建议”**，业务类别精简为“勘误纠错”与“体验建议”；
3. **隐藏外包与留言入口，转由官方原生客服承接**：
   - 在提审期间，在【我的】页面中彻底隐藏“意见反馈与定制留言”及“技术外包定制”入口；
   - 所有咨询需求统一由合规的官方**【在线微信客服】（`open-type="contact"`）**无缝承接。官方客服属于微信平台原生支持的基础通信能力，既不违规，又能实现手机端秒级接待！
