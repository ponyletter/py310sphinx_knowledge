# 虚拟支付（米大师/XPay）与用户隐私保护指引配置

如果你的小程序涉及任何**“数字化虚拟商品”**（如电子书、专栏阅读权限、积分点数、会员特权），微信官方有着极其严苛的专门通道和准入规则。普通微信支付（JSAPI 现金支付）会被直接判定为违规。本章详细拆解**微信虚拟支付 2.0（XPay）**的接入全流程与**用户隐私保护指引**的合规设置。

---

## 1. 为什么数字内容不能走普通微信支付？

微信生态对商品类别有着泾渭分明的划分：

```{mermaid}
graph TD
    Goods[用户发起付款] --> Physical{商品形态}
    Physical -->|实物电商/生活服务| PayA[普通微信支付 JSAPI / 微信商户平台]
    Physical -->|数字内容/专栏/积分/会员| PayB[微信虚拟支付 2.0 XPay / 米大师平台]
    PayA --> CheckA[走快递物流与订单履约，免收苹果抽成]
    PayB --> CheckB[微信官方托管代币体系，统一合规清算]
```

### 1.1 违规后果与平台红线
如果在数字内容（技术文档专栏）中直接调用传统的微信商户 JSAPI 支付唤起微信收银台，在提交版本审核时会遭到**100% 秒拒**，驳回理由通常为：
> *“小程序涉及虚拟支付，iOS 端不可提供任何购买、支付、充值行为，安卓端必须接入微信虚拟支付能力。”*

## 2. 微信虚拟支付 2.0（XPay）接入实战

微信推出了全新一代虚拟支付系统（**XPay / 微信小游戏与小程序虚拟支付**），由微信官方直接向开发者结算。

### 2.1 开通申请流程
1. 登录微信公众平台 ➔ 左侧进入【功能】➔【虚拟支付】；
2. 签署《微信小程序虚拟支付服务协议》；
3. 提交结算银行账户信息（企业或个体工商户对公/法人对私银行卡）；
4. 获得核心商户参数：
   - **Offer ID（业务标识）**：例如 `145064****`；
   - **沙箱 AppKey（测试专用）**；
   - **现网 AppKey（生产上线专用）**：例如 `235lCegHtBLT****************`。

### 2.2 沙箱环境 vs 现网环境切换法则（极度关键！）

| 环境类型 | `env` 参数 | 适用场景与特性 |
| :--- | :--- | :--- |
| **沙箱测试环境** | `XPAY_ENV=1` | 用于本地开发联调。开发者可以使用虚拟测试货币进行扣款，**不会产生真实银行资金扣款**。此环境仅限开发者微信白名单可用。 |
| **现网正式环境** | `XPAY_ENV=0` | **提交平台审核以及发布上线时必须切换为此模式！** 使用真实资金结算，全部微信用户可用。如果在提审时仍保留沙箱环境，审核员验收支付接口时会因非白名单账号报错而判定“功能不可用”予以驳回。 |

### 2.3 道具管理核心设计：价格档位复用法（最佳实践）
在后台【虚拟支付】->【道具管理】中，微信要求每个道具都必须预先录入、定好单价（分）并**点击【发布】生效**。
* **新手常见误区**：按课程标题建道具（如 `douyin_short_video`、`python_sphinx`）。每上线一门新课，都要去后台建一次道具并等微信审核，维护成本极高；
* **行业标杆做法（价格档位复用法）**：
  * `item_100`：单价 1.00 元（100 分，**测试专用档位，必须预置**）
  * `item_990`：单价 9.90 元（990 分）
  * `item_1990`：单价 19.90 元（1990 分，专栏通用）
  * `item_2990`：单价 29.90 元（2990 分）
  * `item_4990`：单价 49.90 元（4990 分）
  * `item_9900`：单价 99.00 元（9900 分）
  **优势**：后续无论上线多少门新课，只要价格是 19.90 元，后端全部映射为 `item_1990`，一劳永逸免维护！
  📥 **配套资源**：[点击下载微信虚拟支付道具批量导入 Excel 模板（标准无特殊符号版）](https://api.yourdomain.cn/uploads/xpay_goods_batch_template.xlsx)（支持后台直接上传）

### 2.4 代币配置（1 人民币 = 1 代币）与底层模式对比
微信后台提供了可选的“代币配置”（支持设置代币名称如“研学币”和换算比例：1 元 = 1 代币）。
* **道具直购模式 (`short_series_goods`)**：专为单篇、专栏、会员等数字化内容打造，用户付款后直接开通目标商品；
* **代币充值模式 (`short_series_coin` / `game`)**：用户先充值虚拟货币到个人账户，再用余额进行内容消费。

### 2.5 商业模式大辩论：“直接购买” vs “充值代币” 哪种转化率更高？
* **专栏直购**：**冲动付费转化率极高**！试读受阻后，1 步微信支付即刻解锁，没有理解门槛；
* **代币充值**：**用户留存与资金沉淀极强**！充值享赠送（充20送2币），账户总有零头余额，促使用户持续复购；且能与签到、邀请等免费裂变活动紧密衔接；
* **双轨融合制（本系统最优解）**：
  * 账户余额充足时：自动展示金色【研学币解锁】；
  * 账户余额不足时：提供【立即直购】与【去充值】双通道，兼顾冲动转化与资金沉淀。

### 2.6 iOS 苹果设备三大硬性红线
个人主体若要在 iPhone 端唤起虚拟支付，必须同时满足以下硬性条件，缺一不可：
1. **微信客户端版本**：必须 $\ge$ **8.0.68**；
2. **小程序简称**：必须在后台【设置】->【基本设置】完成配置（Apple 支付强制规范）；
3. **苹果 IAP 开关**：必须在后台【虚拟支付】->【基本配置】中手动开启“苹果支付”。

### 2.7 生产联调与排雷血泪实录（必读关键避坑）

在真实联调与上线过程中，虚拟支付 2.0 存在几个极易踩坑但官方文档并未显著强调的隐蔽陷阱：

#### 避坑 1：微信支付商户号 (Mch ID) vs 米大师业务标识 (Offer ID) 严格区分
* **高频报错**：`requestVirtualPayment:fail OFFER_ID_INVALID (errno: -15001)`
* **根因剖析**：开发者常将开通虚拟支付时自动生成的 10 位微信支付商户号（如 `175029****`）误填到前端 `signData` 的 `offerId` 参数中。
* **规则**：
  * **Offer ID**：必须是米大师业务 ID（例如 `145064****`），用于标识虚拟支付应用；
  * **商户号 (Mch ID)**：用于微信支付底层的结算与授权，二者绝对不可颠倒。

#### 避坑 2：错误码 `-15001 商户号未绑定` 的四大深层诱因与真机调试机制
* **高频报错**：`requestVirtualPayment:fail 小程序appid和虚拟支付商户号未绑定，可在MP平台点击支付与交易 - 微信支付 - 商户号管理，确认授权申请`
* **深层诱因与化解对策**：
  1. **开发者工具 PC 端模拟器环境限制（最常见假性错误）**：
     日志中带有 `env: Windows, mp, 2.02.xxxx` 表明在 PC 端运行。PC 开发者工具**缺少原生金融收银台组件**，调用现网环境接口会直接报 `-15001`。**必须在开发者工具顶部点击【预览】或【真机调试】，用手机微信扫码在真机上发起测试**；
  2. **商户号确认授权位置找错**：
     开发者往往在【虚拟支付 -> 基本配置】中找确认按钮，但该页面仅为信息展示。真正的授权入口在微信公众平台左侧菜单：**【功能 / 支付与交易】 -> 【微信支付】 -> 【商户号管理】**，在“待确认关联的商户号”中点击确认；
  3. **微信跨平台集群数据同步延迟**：
     新关联商户号或新发布道具后，米大师网关同步通常有 30 分钟 ~ 2 小时延迟，且本地工具需要【清除全部缓存】后重新编译；
  4. **用户态 `session_key` 签名校验隐患**：
     服务端计算 `signature` 必须使用微信登录态真实返回的 `session_key`。若降级为 AppKey 兜底，微信鉴权中心在校验签名不匹配时也会连锁返回 `-15001`。

#### 避坑 3：道具命名字符集红线与 API 直传救场方案
* **官方限制**：微信道具名称**严禁带有英文句点 `.`**（如 `9.9元` 属于非法字符，必须写为 `9元9` 或 `9点9元`），且必须包含 1 元测试档位（`item_100`）；
* **Excel 错传无法撤回时的神级解法**：
  若在后台误传 Excel 道具表且界面无删除按钮，无需慌张，服务端可直接调用微信官方服务端接口 `/xpay/start_upload_goods`，通过脚本批量直传通用档位并覆盖生效：
  ```python
  # 服务端直传通用精简道具档位
  goods_payload = {
      "goods_list": [
          {"product_id": "item_100", "price": 100, "name": "数创研学包1元"},
          {"product_id": "item_990", "price": 990, "name": "数创研学包9元9"},
          {"product_id": "item_1990", "price": 1990, "name": "数创研学包19元9"},
          {"product_id": "item_9900", "price": 9900, "name": "数创研学包99元"}
      ]
  }
  requests.post("https://api.weixin.qq.com/xpay/start_upload_goods?access_token=...", json=goods_payload)
  ```

### 2.8 微信原生在线客服 (`open-type="contact"`) 零门槛接入全流程

很多数字内容小程序需要提供技术答疑、项目定制或专属答疑通道，微信提供了两种接入方式：
* **企业微信客服 (`wx.openCustomerServiceChat`)**：需要企业或个体户认证的企业微信账号，门槛较高；
* **小程序原生在线客服（本方案推荐，个人主体 100% 零门槛）**：
  1. **后台配置**：登录微信公众平台 -> 【功能】 -> 【客服】 -> 点击【添加客服】，输入管理员个人微信号并扫码确认绑定（最多支持 100 位客服人员）；
  2. **前端代码**：仅需使用带有 `open-type="contact"` 的按钮，支持通过 `session-from` 透传咨询场景：
     ```html
     <!-- 个人中心 / 留言页 / 课程锁定页一键直达客服会话 -->
     <button class="btn-service" open-type="contact" session-from="article_douyin_positioning">
       💬 在线微信客服
     </button>
     ```
  3. **手机端实时接待**：用户发消息后，管理员手机微信会实时收到服务通知，直接在微信官方**【客服助手】小程序**中即可打字、发图与学员秒级交流，免装任何独立客户端！

## 3. 《用户隐私保护指引》配置标准规范

自 2023 年 9 月 15 日起，微信对用户个人信息的保护进入最严监管期。未配置或配置不合规的小程序，所有涉及敏感接口（获取头像、写入剪贴板、定位等）将直接静默失效。

### 3.1 必须声明的核心隐私信息项及合规填报模板

进入公众平台【设置】➔【基本设置】➔【服务内容声明】➔【用户隐私保护指引】：

| 收集的个人信息类型 | 接口或行为 | 官方推荐合规使用目的填报模版（即抄即用） |
| :--- | :--- | :--- |
| **用户信息（微信昵称、头像）** | `chooseAvatar`、`type="nickname"` | *“用于在个人中心展示个性化学习档案与专栏会员身份标识，方便用户识别自己的研学进度与资产信息。”* |
| **剪贴板信息** | `wx.setClipboardData`、`wx.getClipboardData` | *“用于快捷复制用户专属 UID、邀请口令、兑换码以及技术支持微信号，提升用户交互便利性。”* |
| **网络信息与存储** | `wx.request`、`wx.setStorage` | *“用于持久化存储用户登录凭证 Token、文章离线阅读缓存以及阅读进度定位。”* |

### 3.2 开发者承诺与注销路径声明
在隐私指引下方，必须勾选并明确填写：
1. **信息保存期限**：选择“在提供服务期间持续保存，用户注销账号后立即删除”；
2. **用户投诉与注销渠道**：填写官方客服微信号或在小程序内提供【意见反馈与留言】通道。
