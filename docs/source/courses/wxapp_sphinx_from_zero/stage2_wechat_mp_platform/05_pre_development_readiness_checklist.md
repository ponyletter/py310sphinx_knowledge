# 微信小程序开发前置核心参数审查清单与道具批量配置指南

在正式动笔写第一行代码或执行部署之前，**前置审查各项平台资质、密匙凭证与业务配置的完整性**，是决定项目能否一次性联调成功并顺利过审的关键。如果某项配置存在隐患（例如商户号与业务 ID 混淆、域名未加白名单、道具名称含有特殊符号），后期往往会导致晦涩的运行时报错（如 `-15001`、`OFFER_ID_INVALID`），排查成本极高。

## 2. 虚拟支付道具配置核心规范

在微信公众平台【虚拟支付 ➔ 道具管理】中录入道具时，必须严格遵守以下规则：

### 2.1 道具 ID 与定价规则
1. **价格单位**：微信官方道具价格单位**全部以“分”为单位（整数）**。1 元需输入 `100`，19.9 元需输入 `1990`；
2. **ID 命名推荐**：推荐采用价格档位通用命名法，如 `item_{金额分}`：
   - `item_100`：1.00 元（100 分）—— **必须预置，便于真机全链路 1 元实测与测试账号验收**；
   - `item_990`：9.90 元（990 分）—— 体验课 / 优惠专栏；
   - `item_1990`：19.90 元（1990 分）—— 主流标准技术专栏通用档位；
   - `item_2990`：29.90 元（2990 分）—— 进阶进阶项目专栏；
   - `item_4990`：49.90 元（4990 分）—— 体系化大课；
   - `item_9900`：99.00 元（9900 分）—— 全站年度 VIP 通票。

### 2.2 道具名称三大禁忌
- ❌ **严禁包含英文句点 `.`**：例如 `9.9元专栏` 会被微信接口直接驳回报错：`道具名称包含不允许的特殊字符（仅支持中英文、数字及 -_*·）`。
- ✅ **正确写法**：必须使用中文描述或汉字代替点号，如 `数创研学包9元9` 或 `数创研学包9点9元`。
- ✅ **道具图片**：建议尺寸为正方形 `200x200` 像素（PNG 格式），外链必须为稳定的 HTTPS 绝对地址。

### 3.2 进阶技能：Excel 无法删除时的服务端 API 直传与覆盖方案
很多开发者在微信后台误传了格式错误的 Excel 后，发现后台**没有提供一键清空或删除按钮**而手足无措。
此时无需等待人工客服，可以直接在服务器端调用微信虚拟支付官方接口 `/xpay/start_upload_goods`，通过一段轻量 Python 脚本将正确的道具集直接覆盖写入：

```python
import requests

def upload_xpay_goods(access_token: str):
    url = f"https://api.weixin.qq.com/xpay/start_upload_goods?access_token={access_token}"
    payload = {
        "upload_type": 1,
        "goods_list": [
            {"product_id": "item_100", "price": 100, "name": "数创研学包1元"},
            {"product_id": "item_990", "price": 990, "name": "数创研学包9元9"},
            {"product_id": "item_1990", "price": 1990, "name": "数创研学包19元9"},
            {"product_id": "item_2990", "price": 2990, "name": "数创研学包29元9"},
            {"product_id": "item_4990", "price": 4990, "name": "数创研学包49元9"},
            {"product_id": "item_9900", "price": 9900, "name": "数创研学包99元"}
        ]
    }
    resp = requests.post(url, json=payload, timeout=10)
    print("微信官方响应:", resp.json())

# 成功返回: {"errcode": 0, "errmsg": "OK"}
```

## 4. 代币体系配置与充值直购双轨模型

在【虚拟支付 ➔ 基本配置 ➔ 代币配置】中：
* **代币名称**：推荐设为“研学币”或“知识币”，契合知识付费心智；
* **换算比例**：设置固定的 `1 元 = 1 代币`（即 100 分 = 1 研学币），直观易懂；
* **双轨制架构设计**：
  * **研学币充足时**：优先触发代币划扣（纯前端交互，零手续费，极速解锁）；
  * **研学币不足时**：直接通过 `mode: "short_series_goods"` 拉起官方微信收银台，实现“缺多少补多少”或“直购专栏”，大幅降低流失率。
