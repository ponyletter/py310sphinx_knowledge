# 需求调研心法与不可变边界锁定

技术外包中最常见的灾难并非技术无法实现，而是**“需求蔓延（Scope Creep）与预期错位”**。客户往往对技术缺乏系统认知，初期仅有一句模糊的想法（如“做个类似滴滴但更简单的软件”），在开发过程中不断临时加需求，最终导致工期无限延期、成本大幅超支，验收时反目成仇。

---

## 1. 客户沟通心理学与专业表达法则

非技术背景的业务客户，往往在面对程序员时存在天然的“技术恐惧与防御心理”。沟通的核心在于**“降低认知门槛、建立掌控感与确定性”**：

```{important}
**客户沟通三大心法：**
1. **摒弃生硬黑话，善用生活物理隐喻**：
   * ❌ 不要对客户说：“你的系统需要做 Redis 缓存防击穿和分布式锁，还要配置 Nginx 动静分离”。
   * ✅ 转换为：“这就好比银行大厅设置了一个快捷取号机和排队叫号通道，防止所有人一下子冲进柜台导致系统瘫痪”。
2. **三问调研核心模型（快速摸清底牌）**：
   * **问目标（到底要解决什么业务问题）**：“这款小程序是用来给线下门店客户核销卡券，还是用来线上商城发快递？”
   * **问底线工期（什么时候必须上线）**：“请问您这个项目最迟必须在什么具体日期交付？是否有特定的活动节点？”
   * **问预算区间（避免无效内耗）**：“为了给您匹配最经济合理的技术选型方案，方便透露一下大概的预算范围吗？”
3. **凡事有交代，件件有着落**：
   * 每天主动在对接群内发送 1~2 句话同步最新进展（如：“今天已完成微信支付接口联调，明天开始接入后台商品管理模块”），给客户极强的安全感。
```

## 2. “不可变需求清单 (PRD)”与签字锁定 SOP

口头约定的需求等于没有约定！在未将需求白纸黑字锁定前，绝不开始写任何一行业务代码。

```{mermaid}
flowchart TD
    Step1["步骤 1：梳理功能脑图 / 模块清单<br/>(按前台用户端 / 后台管理端逐项拆解)"] --> Step2["步骤 2：标注明确的排除范围 (Out of Scope)<br/>(明确写明'本项目不包含XX功能')"]
    Step2 --> Step3["步骤 3：定义可量化的验收指标<br/>(兼容终端 / 响应时间 / 交付物明细)"]
    Step3 --> Step4["步骤 4：微信书面确权回执<br/>(要求客户明确回复'确认按此清单执行')"]
```

### 1. 需求确认书必备四大核心板块

```markdown
# 【项目名称】软件开发功能需求确认单

## 一、交付范围 (In-Scope)
- 模块 1：用户手机号验证码注册与微信一键登录
- 模块 2：商品列表分页展示与关键词搜索
- 模块 3：微信微信支付（JSAPI / 小程序原生支付）及自动回调订单状态
- 模块 4：基础管理员后台（仅支持商品上下架与订单退款审批）

## 二、明确不包含范围 (Out-of-Scope，极度重要！)
- ❌ 本次开发【不包含】多商户入驻与分销裂变功能（若需增加，需作为二期独立计费评估）；
- ❌ 本次开发【不包含】短信发送条数费用与微信商户号申请认证（需甲方自行向服务商支付）；
- ❌ 本次开发【不包含】UI 原创设计（按双方确认的原型默认组件样式交付）。

## 三、可量化验收标准
- 软件在 iOS 16+ 及 Android 12+ 主流移动端分辨率下界面正常无错乱显示；
- 支付成功后 3 秒内订单状态正常变更为“已付款”；
- 交付物包括：编译后部署包、数据库初始化 SQL 脚本、生产环境部署说明文档及项目全套源码。

## 四、工期与变更约定
- 本项目开发周期为 15 个工作日（自甲方支付首款并确认本清单之日起计算）；
- 开发过程中若甲方提出本清单之外的新增或重大修改需求，双方需重新协商增加工期与开发费用。
```

### 2. 微信文字确认的法律效力锁定
需求文档整理完成后，以 PDF 或长图形式发送至对接群，并附带以下确认话术：

> **开发者书面锁定话术**：
> “@甲方负责人 您好，以上是根据我们前序沟通整理的《【项目名称】功能需求确认单》。请您仔细核对功能明细、验收标准及排除项。**如无异议，请在群内明确回复‘确认按此清单执行开发’**。收到您的书面确认后，我们将正式启动开发排期，后续开发与交付验收将严格以此清单为准，感谢您的支持！”

## 3. 工期预估与排期风险控制（Buffer Time 法则）

程序员估算工期时最常见的毛病是**“按照理想状态满负荷预估”**（即假设没有任何 Bug、接口完全顺畅、客户秒级反馈）。现实中各种不可抗力层出不穷：

```{important}
**工期预估 20%~30% 缓冲弹性法则：**
* **实际排期公式**：$$\text{对外承诺工期} = \text{纯开发估算工时} \times 1.3$$
* **预留缓冲抵御四大黑天鹅**：
  1. **第三方接口卡点**：微信商户支付审核不通过、高德地图 Key 限频、短信平台签名被驳回；
  2. **客户反馈滞后**：客户周末失联、确认原型时拖延数天；
  3. **突发本职加班**：兼职开发者遇到公司紧急上线占用业余时间；
  4. **未知底层坑点**：某些冷门依赖库在特定操作系统环境下的兼容性 Bug。
* **提前交付的超预期效应**：如果你预估 10 天做完，对外承诺 13 天；第 11 天顺利交付时，客户会觉得你“工作高效、提前完工、非常靠谱”；若反过来承诺 10 天却在第 11 天交付，哪怕只延误 1 天，也会被判定为“延误工期、不守信用”。
```
