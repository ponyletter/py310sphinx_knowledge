# 【实战复盘】千代：播放量 20w 起号——Codex + 飞书批量提取 100+ 图书视频文案并仿写

> **案例作者**：千代🍂  
> **项目定位**：图书带货 · 视频号文案拆解、批量提取、仿写与配音流水线  
> **核心标签**：`视频号图书带货` `飞书多维表格` `火山引擎豆包` `文案仿写` `wx_channels_download` `自动监听`  
> **实战指标**：20 分钟快速复刻流水线，批量提取 100+ 视频号文案，实操跑出单条 20 万播放成功起号  
> **关键洞察**：图书带货提效的核心不是盲目生成海量泛文案，而是把“对标采集、逐字转录、书名识别、风格仿写与 AI 配音”串联为结构化、可检查的数据流。先跑通流程再优化文案质量，比一开始追求完美更实际。

---

## 一、为什么图书带货需要这套自动化工作流？

在短视频图书带货赛道，**文案是绝对的胜负手**：
- 同一本经典书籍（如《活着》或《晚熟的人》），有人从原生家庭切入，有人切女性成长，有人切职场中年危机，切入角度与文案节奏直接决定了打开率与挂车转化率；
- 研究一个垂直对标博主，往往需要系统拆解其近百条视频的文案脉络。纯手动暂停视频、手打整理文案极其枯燥耗时；
- 视频号不同于抖音，大量图书带货博主没有同步开设抖音号，依赖抖音链接解析的通用工具在此彻底失效。

千代通过 **Codex / Workbuddy + 飞书多维表格 + 火山引擎（豆包语音模型）**，搭建了一条全自动批量处理流水线：

```{mermaid}
flowchart TD
    A["本地工具批量下载视频<br/>(wx_channels_download)"] --> B["Codex 补全扩展名并提取标题/Tag"]
    B --> C["自动写入飞书多维表格并上传视频附件"]
    C --> D["飞书 AI 字段: 火山引擎语音识别提取原文"]
    D --> E["飞书 AI 字段: 豆包识别精准书名"]
    E --> F["飞书 AI 字段: 拒绝套话的高拟真口播仿写"]
    F --> G["飞书 AI 字段: 豆包语音合成自动配音"]
```

## 二、整套系统的标准数据流架构

整条流程跑完后，飞书多维表格将自动形成结构化的多维数据库：

| 字段名称 | 处理引擎 / 来源 | 字段说明与核心规范 |
| :--- | :--- | :--- |
| **文件原名** | 本地文件扫描 | 本地视频的原始文件名 |
| **视频标题** | 正则/AI 提取 | 博主发布的文案标题 |
| **视频 Tag** | 字符串清洗 | 视频携带的话题标签（如 `#图书推荐`） |
| **视频附件** | 飞书 API 自动上传 | 供飞书 AI 视觉与语音模型直接读取的原视频文件 |
| **提取文案** | 火山引擎豆包 ASR | 自动逐字逐句高精度转录的口播文稿 |
| **识别书名** | 豆包 2.0 模型 | 从口语化与封面中抽取的纯净书籍名称 |
| **仿写文案** | 豆包 2.0 模型 | 基于原文风格、同主题但不抄袭的全新原创口播稿 |
| **AI 配音** | 豆包语音合成 | 一键输出对齐文案的高拟真人声音频 |

## 三、小白可照搬的 7 步搭建指南与完整 Prompt

### 步骤 1：让 Agent 连接飞书
- **使用 Codex**：
  ```text
  帮我安装飞书 CLI 工具：
  https://open.feishu.cn/document/no_class/mcp-archive/feishu-cli-installation-guide.md
  ```
- **使用 Workbuddy**：点击左上角连接器，找到“飞书”授权登录，状态显示小绿点即表示连接成功。

---

### 步骤 2：安装视频号批量下载工具并修复扩展名
1. 安装开源下载工具：
   ```text
   安装 wx_channels_download 工具，项目地址是：https://github.com/ltaoo/wx_channels_download
   ```
2. 打开微信 PC 端进入对标博主视频号主页，点击注入的下载按钮，一键下载全部历史视频（如 180 个视频）；
3. **修复漏写扩展名的视频文件 Prompt**：
   ```text
   检查【填写本地视频存放路径】的文件夹中是否有下载器漏写扩展名的视频文件（无扩展名的裸标题文件），
   通过读取文件头（ftyp 标识）确认其为 MP4 格式后，批量自动补上 .mp4 扩展名；全程不删除、不修改任何原始文件内容。
   ```

---

### 步骤 3：让 Codex 自动搭建飞书多维表格

```text
======================================================================
【飞书多维表格自动创建与数据入库 Prompt】
======================================================================
我需要搭建一个视频号文案批量提取和仿写系统。
本地视频保存在：【填写本地文件夹路径】

请连接飞书，并完成以下任务：
1. 扫描指定文件夹中的全部视频文件，告诉我共识别了多少个视频，并与我确认结果。
2. 创建一张名为“【填写对标博主名字】视频号对标文案库”的飞书多维表格。
3. 创建字段：文件原名、视频标题、Tag、书名、视频附件、提取文案、仿写文案、AI配音。
4. 读取每个视频的文件名，识别标题和 tag。
5. 先为前 3 条视频创建测试记录，填写文件原名、视频标题、Tag，并上传视频至“视频附件”，不要填写其他字段。
6. 暂停并发送飞书表格链接，让我确认这 3 条测试记录无误。
7. 确认无误后，继续为文件夹内的全部视频创建记录并上传视频附件。
8. 保留全部本地原始文件，完成后提醒我检查。
======================================================================
```

---

### 步骤 4：配置【提取文案】AI 字段（语音识别 ASR）
1. 双击表格【提取文案】字段，类型选择：**探索字段捷径 $\to$ AI 语音识别（豆包）**；
2. 关联火山引擎账号（登录火山引擎控制台开通语音技术服务，新用户赠送 20 小时免费额度，获取 `Access Token` 与 `App ID` 填入飞书）；
3. 选定引用字段为【视频附件】，点击确认，飞书自动批量将视频语音高精度转录为文字。

---

### 步骤 5：配置【书名】AI 字段（实体抽取）
双击表格【书名】字段，类型选择：**豆包 2.0**，配置指令如下：

```text
根据【@视频标题】和【@提取文案】判断这条视频在推荐、讲解哪一本书，并只输出书名。

输出规则：
1. 只输出书名本身，严禁带《》、书名号、引号或任何解释性说明。例如识别到《活着》就只输出：活着。
2. 书名可能以《书名》形式出现，也可能被口语化提及（如“莫言在晚熟的人里写道”、“余华在这本书里说”），请结合上下文智能判断出准确书名后输出。
3. 若视频并未指向任何具体书籍，则输出：无法识别。
4. 严格基于给定文本信息判断，不要猜测、绝对不要编造未出现过的书名。
```

---

### 步骤 6：配置【仿写文案】AI 字段（核心提示词）
这是整套流水线最核心的提示词，千代通过严苛的“反油腻”与“真人口播化”约束，彻底去除了 AI 常见的大白话假文艺：

```text
======================================================================
【图书带货口播文案仿写 Prompt】
======================================================================
根据【@书名】和【@提取文案】，基于同一本书，仿写一份风格一致、但表达全新的口播文案，严防平台查重判定抄袭。

要求：
- 仿写必须围绕【@书名】所指向的那本书展开；若书名为“无法识别”，则根据【@提取文案】的主题与情绪进行同风格仿写。
- 严格以【@提取文案】本身的风格为范本：它的句式长短、节奏快慢、语气松紧、用词雅俗，你都要照着来，不套用任何你自带的固定 AI 腔调。原稿是短句你就短句，原稿唠家常你就唠家常，原稿严肃你就严肃。
- 说人话！禁止堆砌华丽修辞，禁止生造比喻和套路化感慨。类似下面这种“假文艺、假深沉”表达一律严禁使用：
  “顺开了、拧了好久、戳得发闷、缓两秒、撞过一回墙才知道疼”。
- 不写任何原稿之外的多余情景描写，不硬加多余开头，也不硬加结尾升华。开头就进正题，像原稿那样第一句就抛观点或引出书名。
- 文学感只能来自“自然流畅的叙事”，绝不来自“华丽辞藻的堆砌”。
- 仿写不是搬运，每一个句子都要有原创表述。
- 总字数与语速严格对标原视频文案。
======================================================================
```

---

### 步骤 7：配置【AI 配音】AI 字段
双击表格【AI 配音】字段，类型选择：**AI 语音合成（豆包）**，选择适合严肃文学、情感治愈或商业职场的音色，点击批量生成，每篇仿写文案秒级生成对应配音音频。

## 四、进阶提效与自动化监听

跑通基础工作流后，作者与群友进一步实现了**全自动化监听工作流**：
- 让 Codex 编写一段本地文件监听脚本（基于 Python `watchdog` 库）；
- 只要 `wx_channels_download` 工具在本地文件夹下载完成新的视频文件，脚本自动捕获事件，调用飞书开放平台 API 创建记录、上传附件并触发 AI 字段批量生成；
- **创作者只需负责在手机端浏览并挑选表现优秀的文案，其他全部后台静默运行**。
