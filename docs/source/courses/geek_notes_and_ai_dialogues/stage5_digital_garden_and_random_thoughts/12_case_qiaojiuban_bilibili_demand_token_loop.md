# 【实战复盘】乔久伴：用 Codex 一个月——日耗从几百到 10 亿 Token 与 B 站带货出单实录

> **案例作者**：乔久伴  
> **作者背景**：生财 6 年资深航海家，自由职业创业者，B 站深海圈一期、二期志愿者  
> **核心标签**：`B站带货` `评论区需求选品` `Token管理` `项目地图` `角色分工选品` `70分闭环` `规则沉淀`  
> **实战指标**：高强度实战一个月，单日 Token 消耗突破 10 亿级别；完整跑通需求采集、选品、参数核验、PPT、口播、配音到成片链路，视频发布次日即实现 B 站真实出单  
> **关键洞察**：模型消耗量本身不是能力，闭环迭代才是。人负责目标、边界、责任与审美；AI 负责资料处理、重复生产、自检、修复与交付。不要追求首版 100 分，先让 70 分的完整结果跑出来，再把每一次偏差沉淀为下一次的执行规则。

## 一、AI 协作三大底层认知转变

在正式上手 Codex 之前，作者没有任何编程或 Agent 开发经验。通过一个月高强度烧 Token 实践，沉淀了三条核心原则：

### 1.1 敢于为完整闭环投入试错成本
- 新手最缺的不是“节省一次 API 调用的雕花技巧”，而是**敢于立刻验证完整想法的试错空间**；
- 如果每一步都战战兢兢担心 Token 消耗，往往连第一版成片都做不出来；
- **投资转化标准**：每一轮消耗都必须留下可复用的资产——沉淀一套提示词、固定一个版式模板、或是更新一条错误禁止规则。

### 1.2 建立只读的项目地图（Project Map）
AI 进入新任务时没有长期记忆。如果让它直接无差别扫描庞大工作区，不仅响应迟缓，而且极易把历史过期代码、草稿与现役生产规则混为一谈。

```text
======================================================================
【39G 庞大工作区只读扫描与项目地图初始化 Prompt】
======================================================================
请仔细理解【填写目标工作区绝对路径】这个本地多项目工作区。
全程保持严格只读，绝对不得新增、删除、移动、重命名、覆盖或格式化目标目录中的任何文件！

执行要求：
1. 查找并读取适用的 AGENTS.md、现役入口、README、状态总账与项目清单；
2. 盘点顶层模块职责、技术栈、Git 边界、现役与历史归档关系、真实完成状态和敏感目录；
3. 遇到多版本或规则冲突时，明确说明权威判定顺序，不得仅按文件名或修改时间擅自选择；
4. 完成后在目标目录外创建一份《AI速览与项目地图文档》，包含：30秒极速理解、目录职责、权威入口、核心工作流、当前生产状态、风险边界与最小接手路径；
5. 最后严格自检验收入口目录零新增、零改动。
======================================================================
```

### 1.3 职责边界划分：人负责审美与责任，AI 负责执行
- **人的职责**：确定选题目标、限定业务边界、承担商业风险、进行审美与事实终审；
- **AI 的职责**：大规模数据提取、分镜与文案生成、格式转换、自动化自检与重复修复。

## 二、评论区需求选品法：颠覆传统参数与销量导向

传统带货选品往往第一步看“哪个佣金高、哪个全网销量大、哪个参数强”，容易陷入同质化与自嗨。乔久伴将选品逻辑彻底倒置：**从 B 站真实用户的评论区寻找真实未被满足的需求**。

```{mermaid}
flowchart TD
    A["在无登录干净环境下检索品类视频 (如: 除螨仪)"] --> B["抓取前 5 条视频的 286 条公开评论与楼中楼"]
    B --> C["AI 清洗去重: 筛选出 172 条真实痛点与 59 条高购买意向评论"]
    C --> D["痛点聚类: 提取真实家庭场景 (养宠/鼻炎过敏/学生宿舍)"]
    D --> E["将痛点反向定义为硬性选品指标"]
    E --> F["输出选品决策 Excel 矩阵并由人工确认"]
```

### 2.1 从评论区洞察的三大真实消费心理
1. **决策困难大于功能匮乏**：用户最大的痛苦不是“产品功能不够多”，而是“型号太杂，到底该买哪一款”。这要求带货内容不能罗列参数，而必须做好**价位分层与人群分流**；
2. **场景诉求天然割裂**：
   - 养宠家庭：核心看猫狗毛发能不能吸干净、滚刷缠不缠毛、倒尘杯时灰尘毛发好不好倒；
   - 鼻炎过敏人群：核心看整机密封过滤性能、出风口是否漏尘引发二次扬尘；
   - 学生与租房党：预算 200 元以内、小巧便携好收纳。
3. **警惕技术噱头词**：热风、UV 杀菌、红外探测等功能，若没有具体温度、作用时间与权威报告证据，消费者已普遍产生免疫，不可将其作为核心卖点。

### 2.2 评论痛点到选品条件的精准映射表

| 评论区高频痛点 | 对应的硬性选品条件 | 视频中重点核验的真实指标 |
| :--- | :--- | :--- |
| **型号太多，不知道怎么选** | 每个价格带只保留角色清晰的 1~2 款 | 同价位是否存在真实的不可替代性 |
| **猫毛狗毛吸不干净/滚刷缠死** | 设立专门的“养宠主力角色款” | 防缠绕结构设计、毛发吸入与清理便利度 |
| **鼻炎过敏，担心二次扬尘** | 将密封过滤级别设为一票否决项 | 多重 HEPA 滤网、排风口密封性与滤芯更换成本 |
| **热风/紫外线疑似宣传噱头** | 缺乏证据时坚决不作为主推卖点 | 实测表面温度、紫外线照射功率与安全性 |
| **机器笨重、推拉累手** | 设立人体工程学淘汰红线 | 整机重量、滑轮阻力与长时间单手握持疲劳感 |

## 四、七步闭环 SOP：把单次交付沉淀为持续运行的系统

```{mermaid}
flowchart LR
    S1["1. 定义最终交付物"] --> S2["2. 输入好坏双向案例"]
    S2 --> S3["3. 明确四要素工序<br/>(输入/动作/输出/验收)"]
    S3 --> S4["4. 固化为项目总则"]
    S4 --> S5["5. 真实小任务试跑"]
    S5 --> S6["6. 偏差回滚校准"]
    S6 --> S7["7. 冻结规则并循环迭代"]
```

1. **第一步（明确交付标准）**：清晰告知 AI 最终交付物包括选题、选品矩阵、口播脚本、分镜 PPT、配音与剪映草稿，基础信息处理不交回给人；
2. **第二步（好坏案例对照）**：同时投喂“优秀的满分脚本”与“通篇堆砌参数的失败案例”，让 AI 先分析并输出《项目执行标准草案》；
3. **第三步（四要素工序拆解）**：每个工序明确“谁来做、输入什么、输出什么、质检指标是什么”；
4. **第四步（编制项目总则）**：将权威入口、降级策略、提问限制固化为标准规范；
5. **第五步（真实小任务试跑）**：用 3 款产品的小规模样本验证整套流程连贯度；
6. **第六步（底层偏差回滚）**：若口播风格走偏，坚决不在错误基础上打补丁，直接回滚到最近确认正确的模板重新校准；
7. **第七步（冻结有效规则）**：经过 2~3 轮真实出片验证后，将有效规则固化为正式 Skill，赋能下一次批量生产。
