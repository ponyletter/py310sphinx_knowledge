# 【实战复盘】林幻雨：建筑设计师做 B 站好物——视频产出从两周 1 条提速到 1 小时 1 条

> **案例作者**：林幻雨  
> **作者背景**：主业从事建筑设计，副业深耕 B 站好物带货与 AI 编程；生财深海圈志愿者  
> **核心标签**：`B站好物带货` `桌面内容工厂` `RPA+API混合采集` `京好客穿透` `剪映时间线对齐` `Remotion` `Agent化`  
> **实战指标**：工具版本迭代至 V4.3，视频初稿产出时间从最初的 2 周/条大幅压缩至 1 小时/条以内（全自动草稿生成仅需 5~15 分钟）  
> **关键洞察**：所谓“内容工厂”，绝不是做一个全自动按钮让 AI 从头包办到尾，而是把混乱、重复的工序拆成稳定的流水线——每个模块都有明确的输入、输出与人工质量门禁。数据采集结构化、生产流程分步解耦、中间结果版本留痕，是工业化内容生产的基石。

## 二、采集模块攻坚：RPA、API 与混合采集架构

在商品横评视频中，**原材料的准确性决定了后续一切文案与对比的上限**。作者设计了三层采集防御体系：

### 2.1 RPA 采集模式（应对动态懒加载与复杂页面）
- **懒加载（Lazy Load）对抗**：电商详情页必须随着鼠标滚动才能触发后续渲染。RPA 模拟真人视线匀速向下滚动，确保 70+ 张长图全部加载完毕；
- **弹窗多轮捕获**：针对评论区弹窗滚动销毁历史 DOM 的特性，采用“滚动一屏 $\to$ 抓取快照 $\to$ 追加存储”的分页采集算法；
- **统一任务中心**：每次采集独立建立任务，失败任务可随时单独重试，程序崩溃重启后精准恢复现场。

### 2.2 API 采集模式（毫秒级极速拉取与跨平台穿透）
纯网页爬取速度慢且易触发滑块风控，作者探索出了基于 API 的高效穿透路径：
1. **困境**：京东官方开放平台查询商品详情必须传入商品的 `itemIds`，但普通推广者只有京粉短链，在商品网页上看不到该底层 ID；
2. **跨平台破解方案**：
   - 接入第三方【京好客】API，通过京粉推广短链查询基础信息，解析出隐藏的 `itemIds`；
   - 拿着 `itemIds` 回调京东开放平台官方接口，获取完整的产品参数规格；
   - 将两个接口返回的 JSON 进行数据归一化合并，毫秒级输出结构化字段。

### 2.3 API + RPA 混合采集与参数矩阵导出
- **混合采集机制**：采用 `if-else` 分级策略——先由 API 秒级拉取主数据，若关键参数缺失，自动无缝启动轻量 RPA 打开网页补齐缺漏字段；
- **参数矩阵与横评推荐**：
  - 系统自动统计 5 款竞品中每个参数的存在百分比（如屏幕刷新率存在率 100%，某冷门型号编码存在率仅 20%）；
  - 提供“横评推荐”一键筛选高频核心差异参数，一键导出用于制作 PPT 的 CSV 矩阵。

## 三、生产模块：把自动化与人工确认完美结合

很多 AI 视频工具的最大问题是“黑盒全自动”——模型一旦重新生成，人类之前精心修改的所有文案与布局瞬间被冲毁。林幻雨在生产端建立了严格的工程防线：

```{mermaid}
flowchart LR
    M1["本地内容库中心<br/>(原始素材/拆解/结构化资产)"] --> M2["AI 文案工作台<br/>(按段落切分，单段重新生成)"]
    M2 --> M3["发布助手<br/>(标题/简介/标签/置顶评论)"]
    M2 --> M4["对比页 PPT 制作<br/>(单背景底图 + 预留文字插入)"]
    M4 --> M5["视频编排中心<br/>(以配音时间戳为基准对齐轨道)"]
    M5 --> M6["剪映可编辑草稿"]
```

### 3.1 本地内容库：构建属于自己的资产中枢
内容库不是简单的书签夹，而是分为三个清晰层次：
1. **原始素材层**：导入的 B 站高赞视频字幕、专业测评文章、用户痛点笔记；
2. **清洗与拆解层**：AI 自动剔除废话，解构其“前 30 秒留人钩子、卖点论据逻辑、转场过渡句”；
3. **可复用资产层**：形成标准化的开头模板库、痛点反转库、结尾引导话术，供后续生产随时调用。

### 3.2 AI 文案工作台：段落解耦与历史版本留痕
- **拒绝大段纯文本**：文案被严格切分为【开头、痛点、产品 1 介绍、核心卖点、对比分析、推荐结论、结尾】等独立结构化段落；
- **局部微调不伤全局**：若仅对“产品 1 介绍”不满意，可单独命令 AI 仅重新生成该小段，其余段落、参数与商品顺序纹丝不动；
- **历史版本追加（v1, v2, v3）**：每次生成均建立快照，用户可随时回滚到任意历史版本，并将满意版本标记为“最终锁定稿”。

### 3.3 对比页 PPT：单背景图 + 预留文字槽位
- 早期让 AI 整体画 PPT 极易出现文字溢出、排版错乱的 Bug；
- **极简破解法**：预先设计一套高质感的固定版式背景底图（留出标题区、参数栏与商品图片槽位），程序直接读取商品矩阵数据，精准将文字渲染到预留坐标中；
- 导出时自动生成各商品列的“逐列高亮对比图”，完美配合讲解节奏。

### 3.4 视频编排中心：以配音时间戳驱动剪映轨道
这是全流程中最关键的技术闭环——**如何将静态的文案与 PPT 自动映射为剪映草稿？**

1. **确定绝对基准（时间线）**：任何画面动作必须服务于配音。首先调用 Minimax / 豆包语音合成音频，获取带有精确毫秒级时间戳的字幕文件（SRT）；
2. **片段语义锚定**：将文案段落标记与配音时间戳对齐，系统明确知晓“01:23~01:45 是在介绍第二款商品”；
3. **草稿轨道装配**：脚本自动生成剪映原生草稿 JSON，在对应时间区间内精准铺设 PPT 高亮图、商品主图素材、音轨与字幕，创作者打开剪映即可直接播放。

## 四、与 Codex 的高质量协同技巧

作为非专业程序员，林幻雨分享了两条最实用的提效秘诀：

### 4.1 F12 精准元素定位法（拒绝 AI 盲猜）
在开发浏览器采集或网页解析时，切忌说“帮我抓一下那个价格”：
- 浏览器按 `F12` 打开开发者工具，点击左上角“检查元素”指针；
- 点击页面上的价格区域，在 Elements 面板右键选择 `Copy -> Copy element`；
- 将完整的 HTML 代码片段（如 `<div class="p-price"><span class="price">399</span></div>`）直接粘贴给 Codex，并告诉它提取该标签下的数值。AI 零幻觉，一次写对解析选择器。

### 4.2 苏格拉底提问与 SPEC 梳理 Prompt
```text
我要做一个：【从 B 站置顶评论批量提取京东带货短链并自动触发 RPA 采集的模块】。
请你先不要写代码，你需要：
1. 像苏格拉底一样，帮助我梳理需求；
2. 你需要一个问题一个问题地问，每次都给出带编号的选项；
3. 直到我们能够形成一份完整的 SPEC 文档，符合以下五个标准：
   • Problem Statement（问题陈述）
   • Proposed Solution（方案描述）
   • Technical Constraints（技术约束）
   • Non-goals（明确不做的事）
   • Success Criteria（成功标准）
```

## 五、未来架构演进：解耦、Remotion 动效与 All in Agent

1. **双软件解耦拆分**：将庞大的软件拆分为独立的【采集资产整理工具】与【内容生产加工工具】，二者仅通过标准化的“商品资产包 JSON”进行协议通信，互不干扰依赖；
2. **Remotion 代码级动态包装**：引入开源框架 Remotion，用 React 代码直接将参数矩阵渲染为极具科技感的动态 MG 动效短片段，告别呆板的静态翻页 PPT；
3. **All in Agent 终极形态**：创作者未来只需对系统说一句话：“用这 5 款扫地机做一条 8 分钟 B 站横评，重点比吸力与越障，采用理性测评风格”，由主控 Agent 自动调用各子模块完成物料核验、文案撰写、时间线排布并交付终验剪映草稿。
