## 一、 公众号自动化的核心痛点与解构

“一键生成公众号文章并自动发布”是很多创作者的梦想，但实际落地往往卡死在边缘技术陷阱中：
1. **内容来源虚假**：AI 凭空捏造案例与个人经历，毫无信任感；
2. **排版失真难看**：网页复制到微信后台后，字体、字号、间距、色块完全错位；
3. **接口鉴权复杂**：微信公众平台对调用接口有极其严格的 AppSecret 凭证与 IP 白名单安全策略。

```{mermaid}
flowchart LR
    S1["1. TikHub 数据搜索<br/>(对标数据与真实指标)"] --> S2["2. 选题与查重卡片"]
    S2 --> S3["3. 本地 Obsidian RAG<br/>(观点/原话/案例证据召回)"]
    S3 --> S4["4. 活人感写作 Skill<br/>(去AI味与长短句节奏)"]
    S4 --> S5["5. ImageGen 图片计划<br/>(封面与内页图按比例生成)"]
    S5 --> S6["6. 语义 HTML 排版"]
    S6 --> S7["7. 微信草稿箱 API<br/>(自动上传素材与创建草稿)"]
```

> **自动化核心准则**：**未经人工确认，绝不直接发布。** 系统自动化至“送达微信公众号官方草稿箱”为止，最后由创作者在手机端打开【订阅号助手】检查 1 分钟后手动点亮发送。

## 二、 【核心资料】Codex 技术负责人初始化提示词

以下为根源驱动 Codex 从零搭建“公众号自动化内容工作台”的技术总纲指令：

```text
你现在是这个项目的技术负责人。请在当前目录创建一个可本地运行的“公众号内容工作台”，不要只输出方案，必须完成代码、运行、测试和使用说明。

目标流程：
1. 输入关键词或手动输入候选标题；
2. 从合规数据源（TikHub）搜索候选文章与公开指标；
3. 保存来源URL、标题、作者、时间、阅读/点赞/评论等可获得数据；
4. 对候选内容去重、排序并生成选题卡；
5. 读取本地知识库（Obsidian）的人格语料，进行 RAG 片段检索；
6. 驱动活人感写作 Skill 生成文章正文与关键观点；
7. 运行事实核查，标记证据缺口；
8. 依据正文生成 image-plan，生成封面图（2.35:1）与内页插图（16:9）；
9. 将正文与图片渲染为公众号专用的语义化 HTML 样式；
10. 调用微信公众平台草稿箱 API 上传永久图文素材；
11. 返回草稿 media_id、标题、执行日志和失败原因；
12. 所有阶段支持单步单独重跑，已经成功的阶段严禁重复扣费或重复上传。

安全红线：
- 未经我确认，绝不自动发布，只允许进入草稿箱；
- API Key 与微信 Secret 只能从环境变量中读取，严禁硬编码。

目录结构建议：
├── src/
│   ├── providers/       # TikHub 与微信 API 适配器
│   ├── rag/             # 本地知识切片与检索
│   ├── templates/       # 公众号 HTML 排版模板与提示词
│   └── workflows/       # 调度各阶段的主管线
└── output/              # 每次运行产生的 raw 数据与日志
```

## 三、 数据搜索与证据链：TikHub 适配器设计

不靠 AI 盲目猜测选题，必须从真实世界中已被验证的爆款数据开始：
- **为什么选 TikHub？** 普通无头浏览器爬虫极易被微信验证码滑块拦截，且难以稳定提取点赞、在看与评论量。TikHub 提供了稳定规范的公众号、小红书与抖音数据接口；
- **环境变量约束**：API Key 统一由 `DATA_PROVIDER_KEY` 注入；
- **原始数据留存**：所有接口响应保存至 `output/<runId>/raw/`，确保后续争议可审计；
- **去重与证据等级**：对候选文章进行 URL 规范化与 sourceId 唯一哈希去重；指标完整度 $\ge 2$ 的才判定为“已验证对标”，否则标为“低置信度候选”。

## 四、 本地 Obsidian RAG：拒绝整库灌入

真正可控的本地知识库检索不是把几千篇笔记一次性塞给模型，而是精准片段召回：

```
Obsidian 本地 Markdown 笔记
  ├── 1. YAML 元数据过滤 (必须含 title/tags，private 笔记严格拦截)
  ├── 2. 语义切片 (按三级标题与自然段切割，单片 300~900 字，保留 sourcePath)
  ├── 3. 双轨检索索引 (SQLite FTS5 全文索引 + 向量 Embedding 语义检索)
  └── 4. 降级保底容灾 (当外部向量 API 欠费或异常时，自动退回 FTS5 关键词检索，整机绝不崩溃)
```

## 五、 直连微信公众号官方草稿箱与 IP 白名单攻防

要让做好的文章、封面图与插图自动送进公众号草稿箱，需要调用微信公众平台的 `draft/add` 与 `material/add_material` 接口。

| 配置关键项 | 获取位置与规范 | 避坑与安全规范 |
| :--- | :--- | :--- |
| **AppID** | 微信公众平台 $\rightarrow$ 设置与开发 $\rightarrow$ 基本配置 | 开发者唯一凭证，配置在 `.env` |
| **AppSecret** | 微信公众平台 $\rightarrow$ 基本配置 $\rightarrow$ 开发者密码 | 核心机密，只存放在本地私有环境变量，严禁提交 Git |
| **IP 白名单** | 微信公众平台 $\rightarrow$ 基本配置 $\rightarrow$ IP 白名单 | 必须将发起 API 请求的服务器公网 IP 加入白名单 |

### 针对家庭/本地网络“动态浮动 IP”的三种解决方案

1. **方案一：部署在轻量云服务器（最推荐）**
   - 购买一台腾讯云/阿里云轻量服务器，拥有固定公网 IP，将 IP 一次性录入微信后台白名单，永久无需再动。
2. **方案二：云端代理与 Serverless 转发**
   - 本地写完文章后，将渲染好的 HTML 打包推给固定 IP 的 Serverless 函数，由云端代发微信草稿箱。
3. **方案三：双周集中批处理模式（免买服务器）**
   - 若不想购买云服务器，由于家用宽带 IP 每隔几天甚至每天变化，建议创作者**每两周集中处理一次**：利用周末集中生成未来两周的 10~14 篇稿件，修改一次当前本地宽带公网 IP 进白名单，一次性全部推入草稿箱，一个月只需改 1~2 次白名单。

## 六、 【核心资料】Codex 端到端 12 步验收测试提示词

系统搭建完毕后，必须运行全流程冒烟测试。以下为根源实测通关的**端到端验收指令全文**：

```text
请对这个公众号内容工作台做一次端到端验收，不要只检查代码：
1. 用一个新关键词创建 runId；
2. 搜索候选内容并核对至少 3 条来源 URL 与指标；
3. 展示 RAG 召回的观点、原话、案例、方法和风格片段，确认没有 private 资料；
4. 生成文章，并列出每个真实案例和数字的 sourcePath；
5. 运行事实缺口检查，缺证据的内容不得保留成确定说法；
6. 生成 image-plan。只有会员 image_gen 可用时才生成最终图片；否则标记暂停，不走任何 API 付费回退；
7. 生成公众号 HTML，用手机宽度预览，检查标题、段落、图片和链接；
8. dry-run 验证微信上传请求；
9. 如果我已经提供测试账号与明确授权，只创建草稿并返回 media_id，不发布；
10. 模拟一次上传失败，确认可以从 wechat_draft 单步重试，不会重新搜索、写作或生图；
11. 运行全部测试和构建；
12. 最后输出：成功
```
