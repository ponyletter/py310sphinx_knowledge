# 【实战复盘】舒然：用 Codex 做 AI 图书视频——小白也能跑通的全自动生产流水线

> **案例作者**：舒然  
> **项目定位**：图书短视频带货 · 飞书多维表格生产看板与全自动制片流水线  
> **核心标签**：`AI图书视频` `飞书多维表格` `单样本测试` `视觉安全区` `Whisper强制对齐` `连续旁白生成`  
> **实战指标**：从首条视频默默出单的长尾正反馈出发，日消耗上亿 Token 调试标准，打通飞书多维表格一口气自动连跑 30+ 本书的批量视频生产  
> **关键洞察**：效果绝不会一开始就让人满意，调试的核心在于“拿一本书把标准调透，再将合格标准固化为 Skill 并接入多维表格生产看板”。AI 负责批量执行，人牢牢把守两道闸门：文案的角度确认与成片的终审验收。

---

## 一、项目起点：意外出单带来的长尾商业信心

作者最初在 3 月份陪家人做视频号图书带货，用豆包生图与手动剪辑做了 7 条视频发完便搁置了。然而到了 7 月初，视频号带货助手突然弹出了多笔分佣结算通知——**第一批发布的视频在数月后依然具有持续默默出单的长尾效应**。

看到图书带货的高佣金与持久长尾生命力后，作者决定彻底抛弃效率低下的人工手搓，借助 **Codex + 飞书多维表格** 打造工业化生产流水线。

---

## 二、单样本测试法：拿一本书打磨出“及格线标准”

许多新手搞自动化最常犯的错误，就是一上来直接批量跑 50 本书，结果批量生成出 50 条充满机械感、音画不同步的残次品。

作者严格遵循**单样本调优原则**：先选定 1 本书，不计成本反复打磨，直到跑出一条完全达到商用发布标准的样片，再将其固化为全自动模板。

```{mermaid}
flowchart TD
    S1["1. 选定单本书籍"] --> S2["2. 严卡文案 3 个角度<br/>(人工明确确认)"]
    S2 --> S3["3. GPT 原生批量生图<br/>(严格划定 9:16 纯画面)"]
    S3 --> S4["4. 提取对标音色 + 连续旁白生成<br/>(拒绝单句拼接割裂)"]
    S4 --> S5["5. 视觉三段式安全区排版"]
    S5 --> S6["6. Whisper 强制音画对齐"]
    S6 --> S7["7. 固化为自动化 Skill 并连入飞书"]
```

## 三、五大制作环节的关键避坑指南与 Prompt

### 3.1 环节一：文案把关（人工确认机制）
大模型的泛化文案极易写成生硬的“图书推销说明书”或堆砌辞藻的伪文学。作者在此处设立了**严格的人工确认红线**：

```text
======================================================================
【图书短视频多角度文案构思 Prompt】
======================================================================
我们正在测试《书名》的图书短视频，请先不要生成任何图片或视频！
请先为这本书策划 3 个切入角度完全不同的口播文案方向，每个方向都必须明确写清：
1. 目标受众画像（例如：35岁迷茫中产、刚入职场的年轻人、原生家庭受害者）；
2. 前 3 秒黄金抓人钩子；
3. 戳中受众的痛点、痒点与爽点；
4. 逐字逐句的口播稿全文。

要求：
- 严禁出现任何硬广推销字眼；
- 严禁机械总结全书目录；
- 严禁生造作者未表达的事实；
- 在我明确回复“确认文案”之前，绝对不得生成任何音频、图片或执行下一步！
======================================================================
```

---

### 3.2 环节二：纯画面生图（禁止字画混生）
文案确认后，AI 推导画面分镜。作者指出：
- **禁止在图上直接生成中文字**：AI 在生图模型中直接嵌中文极易出现文字失真变形；
- **提示词必须锁死纯画风**：

```text
根据文案拆解视觉节拍，为每个节拍自动编写生图提示词，提示词中必须固定包含：
- 原生 9:16 竖版构图（禁止用横图暴力裁切）；
- 详尽描写画面中的人物特征、动作、具体环境、年代质感、光线与情绪基调；
- 画面顶部留出放置书名、栏目的留白空间；
- 画面中部留出字幕留白空间；
- 【负向提示词】：严禁生成任何文字、水印、LOGO、二维码、边框与 UI 元素；
- 同一本书的所有插画，必须严格保持统一的年代感、角色画风与色彩基调。
```

---

### 3.3 环节三：声音设计（连续旁白与 BGM 规则）
- **音色固定**：直接让 Codex 提取优秀对标账号的原音音色进行固定克隆，避免每个视频人声漂移；
- **拒绝单句拼接**：人声旁白必须**整篇一次性生成**！如果按分镜一句一句生成再拼接，停顿与声调会极其生硬割裂；
- **BGM 伴奏**：轻音乐伴奏绝对不能压过人声，且在成片结尾必须做淡出处理。

---

### 3.4 环节四：视频画面的“三段式安全区”黄金规范
为了防止视频发布到视频号或抖音后，关键信息被右上角点赞按钮、底部进度条或顶部返回栏遮挡，作者总结了严谨的安全区法则：

| 画面垂直区域 | 占比与空间 | 视觉布局与内容排布原则 |
| :---: | :---: | :--- |
| **顶部安全区** | 约占高 $25\%$ | • 固定放置：栏目名称、书名、作者标签<br>• 背景必须保持极简纯色，**绝不能放置人脸或核心视觉物件** |
| **中部安全区** | 约占高 $30\%$ | • 固定放置：核心加粗动态字幕<br>• 画面呈现墙面、天空、桌面、迷雾等低细节背景，确保文字对比度极佳 |
| **中下部及边缘** | 约占高 $35\%$ | • 放置人物面部、双手动作、剧情核心冲突道具<br>• 巧妙避开正中字幕落点区域 |
| **底部保留区** | 约占高 $10\%$ | • 仅作为画面边缘过渡，不承担任何关键视觉信息（避开平台评论与输入框） |

---

### 3.5 环节五：Whisper 强制音画对齐与防覆盖原则
```text
请按以下标准流水线构建视频工程：
连续旁白生成 
  → 人声音频连续性自检 
  → 最终成品音频输出 
  → 调用 Whisper / StableTS 提取精准字级时间戳 
  → 用人工确认的文案稿强制对齐字幕时间线 
  → 渲染输出合成视频。

【防灾要求】：视频若有任何修改迭代，成片必须保存为 V2、V3，严禁覆盖旧文件，确保随时可回退！
```

## 四、接入飞书多维表格：一人掌管 30 本书的自动生产看板

当单样本测试达到 100% 满意后，作者让 Codex 将其打通至**飞书多维表格生产看板**：

```{mermaid}
graph LR
    User["用户在飞书表格中<br/>批量填入 30 本书名"] --> Codex["Codex 后台自动轮询任务"]
    Codex --> Pipe["自动抓取信息 -> 撰写文案<br/>-> 批量生图 -> 旁白合成 -> 渲染成片"]
    Pipe --> QA{"质检脚本自检"}
    QA -- 未通过 --> Fix["自动重试修复"]
    QA -- 通过 --> Next["自动触发下一本书制作"]
```

### 批量执行总控指令
```text
请根据关联的飞书多维表格开始批量图书视频生产：
1. 读取“待处理”状态的书籍记录；
2. 严格按照预设的高质量标准执行全套制作；
3. 每完成一个视频，依据设定标准进行工程质检；
4. 质检未通过则在本地自动修复重跑；
5. 质检通过后回填视频文件，并自动开启下一本书的制作，直到完成表格中所有书籍；
6. 运行期间遇非阻断异常记录日志，不得擅自中断总任务！
```

## 五、模型选型实测经验
- **GPT-5.6 (High)**：速度极慢，生成单条成片耗时接近 4 小时，完全无法用于工业化批量；
- **GPT-5.6 (Medium)**：质感与速度平衡最佳，约 **40 分钟产出一条高质量成片**，稳定性高；
- **GPT-5.5 (Low)**：约 20 分钟极速出片，但画面细节偶尔出现波动。
