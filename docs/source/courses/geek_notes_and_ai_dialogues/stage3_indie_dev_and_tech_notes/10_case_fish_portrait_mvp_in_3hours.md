# 【实战复盘】Fish 嗡嗡鱼：拾光肖像馆 0 行手写代码 3 小时上线次日收款

> **案例作者**：Fish（嗡嗡鱼）  
> **作者背景**：十多年老全栈开发者，操盘过数十个出海工具站与独立产品，AI 编程航海导师  
> **项目定位**：AI 图像类轻产品 · 【拾光肖像馆】（AI 复古/艺术肖像写真生成）  
> **核心标签**：`0行手写代码` `3小时MVP` `次日收款` `极端需求收敛` `反向架构设计` `真实性审查`  
> **实战指标**：全程不手写一行代码，3 小时内完成产品收敛并提交微信审核上线，上线次日即收到真实用户的付费充值  
> **关键洞察**：3 小时做出 MVP 的核心不是打字快，而是敢于砍掉登录、支付、后台等繁琐非核心环节。AI 时代技术实现已变成大宗廉价商品，真正无法外包给 AI 的核心壁垒只有三件事：选题判断、需求收敛以及上线后的真实性审查。

## 一、反向思考：资深工程师为什么往往做不出小产品？

许多拥有十几年架构经验的资深工程师，在自己做独立产品时往往会死在“过度设计”（Over-Engineering）上：

```{mermaid}

    subgraph 工程师思维陷阱 (沉没成本巨大)
        A1["产生一个产品 Idea"] --> A2["搭建微服务与分布式网关"]
        A2 --> A3["设计完备的 RBAC 权限与多租户架构"]
        A3 --> A4["配置自动化 CI/CD 与 Kubernetes 集群"]
        A4 --> A5["耗时三个月未上线，市场窗口关闭，精疲力竭放弃"]
    end

    subgraph 嗡嗡鱼 3 小时 MVP 原则 (敏捷验证)
        B1["锁定一个具体情绪买点"] --> B2["外科手术式砍掉 80% 非核心代码"]
        B2 --> B3["3 小时借助 AI 搓出单页闭环"]
        B3 --> B4["次日推向市场，收到第一笔真实转账验证商业成立"]
    end
```

独立商业的胜负手，从来不是比拼代码写得有多优雅，而是**以最低的试错成本、在最短的时间窗口内，验证到底有没有陌生人愿意为你的解决方案掏出真金白银**。

## 二、3 小时极速上线的极端“砍需求”艺术

为了在 3 小时内做出【拾光肖像馆】，Fish 运用了极其克制的外科手术式裁剪法，将传统软件工程中看似“必不可少”的模块全部剥离：

### 2.1 砍掉独立的账号注册与手机号授权体系
- **传统做法**：设计手机号短信验证码、图形验证码、微信授权弹窗、用户基础信息表、密码加密加盐；
- **Fish 的做法**：完全砍掉！用户打开小程序即自动生成本地无感 Session（或微信内置 OpenID），用户无需授权任何敏感手机号或头像昵称，点击即可直接进入核心体验。零阻力大幅提升首屏转化率。

### 2.2 砍掉复杂的官方微信支付与自动分账系统
- **传统做法**：提交营业执照申请商户号、配置 APIv3 密钥、上传数字证书、手写微信支付回调验签、处理退款与对账状态机；
- **Fish 的做法**：第一版根本不接微信支付！
  - 免费生成低清小样预览；
  - 如果用户满意想要获取 4K 超清写真，页面直接弹出微信个人客服名片或展示专属收款二维码：“添加客服装造师微信，发送预览图即可人工一对一高清精修出图”；
  - 核心逻辑：如果一个用户连加微信手动转账 9.9 元都不愿意，那你花三天时间写的微信支付接口毫无意义；当第一批用户纷纷主动转账时，再花半天时间将支付自动化也不迟。

### 2.3 砍掉管理后台与复杂 CMS
- **传统做法**：开发后台管理系统，提供肖像风格增删改查、提示词管理、用户数据分析看板；
- **Fish 的做法**：直接将 6 款主打的复古风格（如：90年代港风胶片、民国复古旗袍、春日油画肖像）以静态 `config.js` 常量数组形式硬编码在小程序前端；
- 每次增加新风格，改两行代码直接发版，彻底省去维护后台的巨额精力。

## 三、AI 时代无法外包给 AI 的“三大心智底座”

Codex 等智能体的编码速度可以达到每秒数十行，但以下三件事，AI 永远无法代替人类做决策：

```{mermaid}
flowchart TD
    M1["1. 选题判断 (Market Insight)<br/>什么样的需求具备情绪价值与付费冲动？"]
    M2["2. 需求收敛 (Scope Control)<br/>如何按住 AI 蠢蠢欲动的过度设计冲动？"]
    M3["3. 真实性审查 (Reality Check)<br/>离开本地 IDE，到真实市场上接受用户的毒打"]

    M1 --> M2 --> M3
```

### 3.1 选题判断：锁定具备“冲动消费”的情绪资产
AI 图像工具有成千上万种，为什么做“拾光肖像馆”？
- 纯粹的通用文生图（如输入一段提示词画风景）属于玩具，普通人玩两次就腻；
- 但**与用户自身形象深度绑定的肖像写真**，属于极度高频且具有炫耀属性的社交货币：小红书头像、朋友圈背景、节日定制贺卡；
- 用户的付费决策通常在 10 秒之内完成，客单价在 9.9 ~ 29.9 元之间，摩擦力极低。

### 3.2 需求收敛：警惕 AI 的“老好人”过度工程
与 Codex 交互时，只要你说“我要做个肖像馆”，AI 会极其热心地主动建议：
- “我们要不要增加积分任务体系，让用户看广告赚代币？”
- “我们要不要支持好友拼团砍价和分销员二级分佣？”
- “我们要不要引入队列重试、死信队列和 GPU 熔断降级？”

此时人类开发者必须具备清醒的**冷酷裁决力**：
> “把所有的积分、拼团、分销全部砍掉。我现在只要一个核心页面：用户传照片 $\to$ 选港风风格 $\to$ 渲染出图。只写这一个流程，其他的全部不要！”

### 3.3 真实性审查：上线才是残酷考验的开始
本地运行流畅（`127.0.0.1`）只能证明代码逻辑没有语法错误，不代表商业价值成立。

真实性审查的核心标准：
1. **微信审核真实性**：服务类目是否合规？生成的 AI 图片是否会触发微信内容安全接口 `security.msgSecCheck`？
2. **用户操作真实性**：用户上传的照片光线不均、五官侧脸遮挡时，生图算法是否会崩溃？生成的照片像不像本人？
3. **商业货币真实性**：用户在看到预览图后，到底会不会真金白银转账？

## 四、极速上线后的正向迭代飞轮

Fish 在次日收到多笔用户主动转账后，迅速验证了商业模式的真实性，随后启动了模块化演进：

| 演进阶段 | 核心动作 | 收益与系统表现 |
| :--- | :--- | :--- |
| **Day 1 (首日上线)** | 0 行手写代码，3 小时跑通核心体验，人工微信收款 | 验证需求真实存在，消除所有盲目投入风险 |
| **Day 2 (次日收款)** | 收到第一笔 19.9 元真实转账，确认商业闭环成立 | 获得最真实的商业正反馈，确定追加研发资源 |
| **Day 3~5 (自动化补齐)** | 让 AI 接入微信官方支付商户号，接入云函数异步生图 | 摆脱人工盯微信收款核销的繁琐，实现 24 小时全自动出图 |
| **Day 7+ (规模化放大)** | 小红书发布真实客照对比，搭建代理分发机制 | 形成“真实订单 $\to$ 资金回流 $\to$ 精细化迭代”的正向飞轮 |

## 五、给独立 Hacker 的精益开发心法

```text
======================================================================
【Fish 极速 MVP 三问】
======================================================================
1. 【能否再砍？】：这个功能如果不做，用户明天还能不能完成交易？如果能，砍掉！
2. 【能否人工？】：这个模块如果先用人工客服/微信转账顶上，能省下多少天开发？如果能省两天，坚决人工！
3. 【能否次日见钱？】：你的产品设计能否在上线 24 小时内，创造出一个让用户掏出手机扫码付款的触点？
======================================================================
```
