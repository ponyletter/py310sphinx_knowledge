# 【实战复盘】✞超人✞：如何用 Codex 制作哈宝桌面宠物与开源引擎

> **案例作者**：✞超人✞  
> **项目名称**：【哈宝桌宠】（macOS 原生桌面宠物 · 3D Q 版哈兰德）与开源引擎 `desktop-pet-engine`  
> **核心标签**：`macOS原生开发` `Swift/AppKit` `角色一致性` `Alpha透明穿透` `8向鼠标追踪` `开源项目`  
> **实战指标**：零代码基础，完整跑通角色 3×3 九宫格设定、官方球衣硬约束、8 方向追踪、透明序列帧处理、鼠标穿透交互与 `.app` 打包，并在 GitHub 开源桌面引擎  
> **关键洞察**：热点与梗图能提供极佳的创意入口，但能否落地取决于角色一致性、素材处理规范与底层交互细节。明确授权与版权边界直接决定了商业化或开源路径；将 AI 视为自检闭环的工程师搭档，能让小白跨越原生桌面开发的鸿沟。

## 一、创意起点与版权边界权衡

### 1.1 从热点表情包到桌面伴侣
在世界杯期间，挪威前锋哈兰德（Haaland）凭借金色长发、霸气庆祝动作以及极具反差萌的夸张面部表情风靡全网。作者在保存了大量表情包后产生了一个灵感：
> “这些表情包如果不仅停留在微信聊天框里，而是能变成一个住在 Mac 屏幕底部的 3D Q 版桌宠，追着鼠标看、无聊时喝水、犯错时抓狂、进球时庆祝，那该多有趣！”

### 1.2 版权合规与开源战略选择
在推进过程中，作者清醒地意识到了版权红线：
- 哈兰德肖像权、挪威足协标志、Nike 品牌商业版权均受严格保护；
- 如果将其做成付费软件直接售卖，面临极高的侵权法律风险；
- **破局抉择**：作者决定放弃商业化变现，将哈宝桌宠作为开源技术演示，并将整套底座提炼为通用的 **macOS 原生桌宠引擎 `desktop-pet-engine`**，在 GitHub 全面开源（采用 Apache-2.0 协议），供开发者替换为属于自己的原创角色。

## 二、素材管线攻坚：如何彻底驯服 AI 的“幻觉与漂移”？

桌宠开发中最核心的痛点不是写代码，而是**素材一致性**——如何保证“喝水、走路、抓狂”的每一帧都是同一个人，而不是换了个衣服、变了脸型？

### 2.1 基础设定：3×3 九宫格角色基准表
切忌一开始就逐个生成动作。正确流程是**先生成一张 3×3 角色情绪设定图**，锁死人物脸型、比例、发型和材质：

```text
======================================================================
【3×3 角色基准九宫格设定 Prompt】
======================================================================
请制作一张 3×3 的角色表情设定表，角色为 3D Q 版哈兰德。
纯绿色纯色背景，固定正面中景镜头，完整全身，四周留出安全边距。
九宫格包含 9 种情绪：正常待机、开心、大笑、得意、生气、惊讶、难过、困倦、疯狂庆祝。

强制一致性约束：
1. 每格必须是同一个人：完全相同的金黄色长发束发、硬朗方下巴脸型、大头小身体 3D 玩偶材质与光照；
2. 严禁出现任何画面文字、水印、UI 边框或提示箭头；
3. 参考真实表情包的神态与肢体语言，但不要照搬背景。
======================================================================
```

### 2.2 终极攻坚：去 Nike 官网截图锁定球衣细节
在生成过程中，AI 频繁出现严重的“球衣漂移”：有时生成曼城天蓝球衣、有时是旧版纯红球衣、深蓝短裤、金鞋乱飞，胸前十字反复变形。继续盲抽只会浪费时间。

#### 破局绝招：官方商品详情页硬约束
作者直接打开 Nike 官方商城挪威国家队 2026 主场球衣页面（款号 `IB5170-673`），截取了正面、胸前十字、队徽、领口的多角度高清单品图投喂给 AI：

```text
======================================================================
【球衣绝对约束校准 Prompt】
======================================================================
请立即停止继续随机生成！先使用我提供的 Nike 官网正品截图校准服装细节：

1. 球衣款式固定为挪威国家队 2026 主场战袍：底色为高饱和亮红（Chile Red）；
2. 胸前必须是大面积深海军蓝（Deep Navy）北欧十字，十字外边缘有清晰纤细的白色包边；
3. 胸前号码固定为 9 号，胸口右侧为白色 Nike Swoosh 标志，左侧为挪威足协队徽；
4. 下装固定为纯白运动短裤、白色高筒球袜、哑光纯黑球鞋；
5. 【绝对禁止项】：严禁退回旧款全红球衣、曼城蓝色球衣；严禁短裤变蓝；严禁球鞋变金色；严禁北欧十字消失、变形或错位！
后续所有动作与序列帧生成必须严格遵循此规范！
======================================================================
```
通过将“主观形容词”替换为“官方商品图 + 严苛正负向约束”，球衣一致性问题迎刃而解。

### 2.3 核心交互设计：8 方向“无鼠标”鼠标跟随
桌宠有没有生命力，关键在于待机时能不能“看向用户的鼠标”。

#### 致命误区：不要在画面里生成假鼠标！
如果提示词写“角色跟随鼠标看”，AI 会愚蠢地在视频画面内部画上一只巨大的白色鼠标光标。

#### 优雅解法：时间轴隐形目标追踪
设计一段 5 秒的 20fps 循环视频，角色依次注视画面外 8 个方向，程序提取 8 个代表帧进行角度映射：

| 播放时间 | 追踪方向 | 20 fps 帧号 | 头部与眼球动作要求 |
| :---: | :---: | :---: | :--- |
| **0.0 秒** | 正中 (Center) | 0 | 自然看向屏幕正前方 |
| **0.5 秒** | 左上 (Top-Left) | 10 | 眼神与头部抬起，朝向左上方 |
| **1.0 秒** | 正上 (Top) | 20 | 向上仰视 |
| **1.5 秒** | 右上 (Top-Right) | 30 | 朝向右上方 |
| **2.0 秒** | 正右 (Right) | 40 | 平视右侧 |
| **2.5 秒** | 右下 (Bottom-Right) | 50 | 俯视右下方 |
| **3.0 秒** | 正下 (Bottom) | 60 | 低头向下看 |
| **3.5 秒** | 左下 (Bottom-Left) | 70 | 俯视左下方 |
| **4.0 秒** | 正左 (Left) | 80 | 平视左侧，随后自然回正 |

```text
【8 方向鼠标跟随 Prompt】
使用同一位 3D Q 版哈兰德角色，纯绿背景，固定正面中景，制作 5 秒平滑动画。
角色的躯干、双腿和站立位置完全固定不动，只允许头部微转与眼睛转动。
角色依次追踪画面外 8 个不可见的悬空目标点：
0.0s 正中 -> 0.5s 左上 -> 1.0s 正上 -> 1.5s 右上 -> 2.0s 正右 -> 2.5s 右下 -> 3.0s 正下 -> 3.5s 左下 -> 4.0s 正左。
【关键要求】：画面内绝对禁止出现任何真实鼠标箭头、瞄准星或辅助线条！首帧与尾帧姿势完全一致。
```

## 三、macOS 原生架构与 Swift/AppKit 实现

### 3.1 总体架构提示词（把任务一次性交代清楚）
作者向 Codex 发送的总控指令，遵循了“目标、上下文、约束、验收标准”四要素：

```text
我想制作一个 macOS 桌面宠物应用，命名为“哈宝桌宠”，角色为 3D Q 版哈兰德。
请先检查我当前项目目录下的素材资源，规划方案并直接开始编写与打包。不要让我手动输入命令。

【目标】：
1. 始终置顶（Floating Window）、无系统边框、透明背景的 macOS 原生桌宠；
2. 待机时根据真实系统鼠标坐标，计算相对角度并显示对应的 8 方向视线帧；
3. 支持鼠标拖拽移动；透明像素区域绝对不能阻挡对下层桌面其他软件的点击；
4. 右键菜单可主动播放：走路（walk）、喝水（drink）、抓狂（frustrated）、害羞（shy）等动作；
5. 空闲时随机触发自主小动作；缺失的动作优雅跳过，禁止程序崩溃；
6. 输出可在 macOS 上直接双击运行的“哈宝桌宠.app”。

【技术约束】：
- 采用 macOS 原生 Swift + AppKit 开发；
- 动画统一处理为透明 PNG 序列帧；
- 遵守 macOS 权限规范，不污染系统全局设置。
```

### 3.3 彩蛋：原生“足球光标”交互实现
当用户的鼠标移入哈兰德实体（非透明像素）时，系统箭头自动变身为一颗 ⚽️ 足球；移出哈宝身体后，立即无缝恢复为系统默认光标：

```swift
// 原生 Swift 足球光标生成与动态响应（核心片段）
private func makeFootballCursor() -> NSCursor {
    let size = NSSize(width: 32, height: 32)
    let image = NSImage(size: size)

    image.lockFocus()
    let paragraph = NSMutableParagraphStyle()
    paragraph.alignment = .center
    let attributes: [NSAttributedString.Key: Any] = [
        .font: NSFont.systemFont(ofSize: 26),
        .paragraphStyle: paragraph
    ]
    ("⚽️" as NSString).draw(
        in: NSRect(origin: .zero, size: size),
        withAttributes: attributes
    )
    image.unlockFocus()

    return NSCursor(
        image: image,
        hotSpot: NSPoint(x: 16, y: 16)
    )
}

private func updateCustomCursor(isOverPetPixel: Bool) {
    if isOverPetPixel {
        footballCursor.set()
    } else if wasHoveringPet {
        NSCursor.arrow.set()
    }
    wasHoveringPet = isOverPetPixel
}
```

## 四、开源项目 `desktop-pet-engine` 与交付清单

作者最终将这套工业级桌面宠物框架在 GitHub 开源：
- **仓库地址**：[https://github.com/InsiderX-Pro/desktop-pet-engine](https://github.com/InsiderX-Pro/desktop-pet-engine)
- **开源协议**：Apache-2.0

### 开源引擎内置资产与能力清单
1. **原生 AppKit 窗口管理**：多显示器支持、置顶悬浮、断电/重启位置记忆；
2. **高效帧渲染器**：基于 Metal / Core Animation 的透明 PNG 序列帧播放器，CPU 占用低于 1.5%；
3. **逐像素 Alpha 点击穿透与拖拽系统**；
4. **8 方向视线追踪数学向量库**；
5. **素材自动化处理脚本（Python CLI）**：一键绿幕/黑底抠像、统一居中对齐、生成 `manifest.json`；
6. **配套 Codex Skill**：可以直接导入 Codex / Claude Code，一句话指令生成专属桌面宠物。

> **作者写在最后**：
> “一个原本不懂 Swift、不懂透明通道、连 Xcode 命令行都没摸过的小白，居然在 GitHub 上发布了一个开源项目。这在过去是天方夜谭。AI 不是只能写点几行的小脚本，只要你敢于把现实生活中的热情（足球、球星、动漫）转化为具体需求，并严格充当裁判做好验收，你就能打造出惊艳全网的原生桌面级产品。”
