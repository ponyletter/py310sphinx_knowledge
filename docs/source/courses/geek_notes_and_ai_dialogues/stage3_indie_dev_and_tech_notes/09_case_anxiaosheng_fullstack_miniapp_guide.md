## 一、课前调研：个人开发者先避开这 4 个致命坑

### 1.1 为什么做小程序而不是独立 APP？
- **APP 成本巨高**：iOS 苹果开发者账号每年 688 元，且安卓各家应用商店（华为、小米、OPPO、vivo、应用宝）上架需要不同的软件著作权（软著）和极严的 ICP 备案；
- **小程序极速试错**：认证迅速，审核周期短（通常 1~2 个工作日），无需用户安装，依托微信庞大社交关系链，天然具备分享与分发优势。

### 1.2 主体与服务类目禁区对照表

```{warning}
**审核红线**：
个人主体与企业/个体户在微信生态中有严格的权限隔离。一旦选错类目，小程序会被秒驳回甚至直接封禁封号！
```

| 开发者主体 | 允许做的推荐类目（轻闭环） | 绝对禁止碰触的类目（高风险） |
| :--- | :--- | :--- |
| **个人主体** | • 工具类：计算器、时钟打卡、图片轻量处理、文案生成、OCR 识别<br>• 内容类：静态壁纸、文案语录、个人作品集（无敏感互动） | • **严禁**：医疗健康、金融理财、社交交友、社区论坛、网络直播/短视频、在线商城下单 |
| **个体工商户 / 企业** | • 具备完整主体资质，可开通所有通用行业类目<br>• **核心特权**：可申请开通**微信支付商户号**，进行会员订阅与虚拟商品结算 | • 仍需根据特定类目补充前置许可证（如食品经营许可证、增值电信业务许可证 EDI/ICP） |

## 二、UI 设计三步法：把脑海想法变成精准界面

很多开发者直接对 AI 说“帮我做个好看的记账页面”，生成出来的往往是千篇一律、字段缺失的粗糙页面。安小生总结了标准的 UI 推进三步法：

```{mermaid}
flowchart LR
    S1["第一步：写需求描述<br/>(明确页面、组件、字段与事件)"] --> S2["第二步：Stitch / ChatGPT 出图<br/>(生成高保真视觉草图)"]
    S2 --> S3["第三步：投喂给 Codex 编写代码<br/>(分页面推进，开发者工具实时编译)"]
```

### 2.1 第一步：需求描述卡编写规范
每次只聚焦单一页面，明确四大要素：
1. **页面定位**：这是什么页面？用户在这个页面的唯一核心任务是什么？
2. **可视组件清单**：顶部导航、汇总卡片、输入框、标签组、提交按钮；
3. **数据字段映射**：如记账页包含金额（数字键盘）、收支类型（收入/支出）、分类标签（餐饮/交通等）、备注、日期；
4. **操作交互反馈**：点击保存后触发校验、弹出 Toast、写入本地或请求后端、返回上一页。

### 2.2 第二步：利用 Stitch 或 ChatGPT 极速出图
- 借助 Google Stitch 或 ChatGPT 的图像生成能力输入界面描述，秒级生成清晰的 UI 视觉效果图；
- 作用：让需求变成“看得见的直观布局”，确定色彩主色调与排版对齐方式。

### 2.3 第三步：交付 Codex 生成原生小程序代码
将 UI 草图结合需求卡投喂给 Codex，明确要求生成原生 WXML 结构与 WXSS 样式，一次只生成一个页面或单个自定义组件，并在微信开发者工具中即时编译预览。

## 三、三大实战场景与标准化 Prompt 模板库

安小生整理了不同难度梯度的 3 个完整实战项目 Prompt 库：

### 案例 1：纯前端轻工具（健康自测打卡盒子）
```text
你是微信小程序高级前端工程师。请帮我设计一个“健康水分打卡助手”单页小程序。
技术栈：微信小程序原生语法（WXML、WXSS、JS、JSON），不使用第三方后端，全部数据存储在本地 wx.setStorageSync 中。

页面结构与交互：
1. 顶部展示今日饮水总量进度环（圆环进度条），目标值为 2000ml，动态展示完成百分比；
2. 中间提供四个快捷打卡按钮：+200ml（一杯茶）、+350ml（一罐水）、+500ml（一瓶矿泉水）、自定义容量；
3. 下方展示今日打卡历史时间线列表（时间戳 + 毫升数 + 删除按钮）；
4. 每天 00:00 自动重置今日数据，历史打卡数据按日期归档；
5. 界面风格：极简奶油风，莫兰迪蓝白色系，圆角微阴影卡片。
请分步给出完整的 index.wxml、index.wxss、index.js 代码。
```

### 案例 2：第三方 API 接入类（城市天气查询）
```text
你是微信小程序工程师。请为我编写一个调用高德地图天气开放接口的天气查询页面。
接口规范：
- 请求方式：GET https://restapi.amap.com/v3/weather/weatherInfo
- 请求参数：key（应用Key）、city（城市编码或名称）、extensions（base 为实时，all 为预报）

要求：
1. 顶部提供城市搜索框与定位快捷按钮；
2. 点击查询后显示 wx.showLoading 状态；
3. 请求成功后渲染主卡片：城市名、天气现象图标、实时温度、风向、风力级别、空气湿度、更新时间；
4. 增加完善的容错处理：当用户输入非法城市名称或网络超时时，弹出 wx.showToast 友好提示，不可白屏崩溃；
5. 在 JS 中对 wx.request 进行 Promise 封装，并说明在微信后台需要将 restapi.amap.com 配置进 request 合法域名白名单。
```

## 四、全栈云基础设施极速搭建（宝塔 + 腾讯云轻量）

对于需要独立后端的项目，安小生推荐了最高性价比的基础设施组合：

```{mermaid}
graph TD
    User["用户手机端微信"] -->|HTTPS 443 访问域名| Nginx["Nginx (反向代理与 SSL 终止)"]
    Nginx -->|FastCGI / 本地端口| App["Laravel 后端应用 (PHP 8.2)"]
    App -->|127.0.0.1:3306 (禁止外网访问)| MySQL["MySQL 8.0 数据库"]
    User -->|静态图片与音频直连| COS["腾讯云 COS 对象存储 (加速 CDN)"]
```

### 4.1 核心配置与实战步骤
1. **服务器选型**：首选**腾讯云轻量应用服务器**（Lighthouse），镜像直接选择自带的“宝塔 Linux 面板”（省去手动在命令行安装面板的复杂步骤），规格 2核2G 4M 即可满足前期数万用户需求；
2. **域名与备案**：腾讯云直接购买 `.com` 或 `.cn` 域名，立即进行实名认证并提交工信部与公安部备案（备案耗时约 1~2 周）；
3. **环境快速部署**：
   - 登录宝塔面板后台，弹窗推荐选择 **LNMP**（Nginx 1.24 + MySQL 8.0 + PHP 8.2）；
   - 安装方式选择“极速安装”（10~15 分钟完成编译部署）；
4. **免费 SSL 证书一键配置**：
   - 在宝塔面板网站设置中，选择“SSL -> Let's Encrypt”；
   - 勾选域名，一键自动签发并开启“强制 HTTPS”，宝塔会自动每 3 个月自动轮换续期；
5. **数据库安全铁律**：
   - MySQL 端口严格保持本地监听（`127.0.0.1:3306`）；
   - 在宝塔面板“安全”选项卡及腾讯云防火墙中，**严禁对公网开放 3306 端口**，防止被全网扫描勒索病毒攻击。

## 五、商业化变现通道与接单报价策略

### 5.1 变现双轮驱动：流量主 + 轻会员
1. **微信流量主广告（门槛：累计 500 UV）**：
   - **Banner 广告**：放置在列表页底部；
   - **插屏广告**：在用户完成一次完整核心操作（如保存账单、导出报表）后合理触发，切忌滥用；
   - **激励视频广告**：观看 15 秒视频，解锁 24 小时高级功能或获取 5 次高级分析额度。
2. **轻量会员订阅**：
   - 个人开发者通过注册个体工商户执照，申请开通微信支付商户号；
   - 采用 6.9 元/月或 39.9 元/终身买断的轻定价策略，降低决策阻力。

### 5.2 商业外包接单防坑与报价计算模型
许多开发者接商单时，往往只按“页面数量”给客户报价（如一个页面 300 块钱，5 个页面 1500 元），最后赔本甚至烂尾。

> **安小生的报价铁律**：
> 商单报价必须将**隐形交付成本**计算在内！

$$\text{最终报价} = (\text{前端页面工时} + \text{后端API与建表工时} + \text{服务器与SSL配置工时} + \text{微信审核与备案周期成本}) \times \text{时薪} \times 1.35 (\text{预留需求变更缓冲})$$

在与客户签署协议前，必须在合同或需求确认书中锁定：
1. **需求冻结线**：首期仅交付 PRD 列明的核心功能，超出清单的微调视作二期迭代，单独计费；
2. **主体与资质归属**：明确客户自行提供营业执照、商户号、服务器与域名，开发方只负责技术交付，不代垫第三方规费；
3. **分期付款节点**：坚持 `3-4-3` 原则（定金 30% $\to$ 原型及核心 API 联调 40% $\to$ 微信审核通过正式上线 30% 尾款），绝不接受全款上线后结清。
