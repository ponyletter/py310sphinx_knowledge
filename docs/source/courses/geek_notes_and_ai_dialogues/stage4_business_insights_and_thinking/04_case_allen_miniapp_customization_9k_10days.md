## 一、 背景与破局：资深工程师的“零小程序”初战

很多传统开发者或技术人会陷入思维误区：“我必须先把某种技术体系（如微信小程序生态、服务器部署、OSS、备案审核等）全部学透，才有资格接商业项目。”

作者拥有 16 年政企软件开发管理背景，但在接单前**从未开发过微信小程序**。借助 Claude Code 和 Codex，作者先开发了 2 个自用内部小程序跑通技术闭环，随后成功承接了外部付费客户的定制单：
- **项目定位：** 一家线下肖像美学机构的小程序，主要用于摄影作品瀑布流展示、客户在线预约排期、以及外部合作渠道的推广溯源与佣金统计；
- **客户预期：** 14 天内必须正式上线运营；
- **商业结算：** 9,000 元项目合同总额。

## 二、 需求降维：42 分钟需求会与 3 条核心闭环切割

项目能够 10 天提前交付的核心，**不仅在于 AI 写代码的速度，更在于前期严控需求边界**。

在与客户仅 42 分钟的线上沟通中，作者敏锐地发现：客户虽然提了一大堆诸如“在线商城、会员储值卡、优惠券裂变、自动打款分账”等宏大设想，但其当前阶段最迫切的痛点是**“业务数据透明可信，避免每次渠道结算在微信群反复人工对账”**。

作者迅速对需求进行了战略级降维切割，只做三条不可妥协的核心业务闭环：

| 角色视角 | 核心业务闭环（一期上线必须实现） | 坚决砍掉并延后至二期的功能 |
| :--- | :--- | :--- |
| **顾客端** | 浏览精选客片与分类作品 $\rightarrow$ 查看作品详情 $\rightarrow$ 提交预约表单 $\rightarrow$ 查验预约与订单状态 | 在线微信支付、会员储值卡、复杂满减优惠券 |
| **门店端** | 发布与维护作品分类 $\rightarrow$ 接收预约提醒 $\rightarrow$ 线下服务完成后录入消费金额 $\rightarrow$ 自动汇总应付佣金 | 自动分账打款、复杂员工排班考勤、库存进销存 |
| **渠道端** | 渠道员工生成专属小程序码 $\rightarrow$ 顾客扫码终身绑定 $\rightarrow$ 实时查看引流人数、消费金额与应结佣金 | 渠道线上自动提现（改在线下按月对账公对公转账） |

```{admonition} 关键认知：客户要做的是业务闭环，而不是金融工程
:class: tip
首期系统聚焦在“**记录、归属、计算与展示**”，砍掉在线支付不仅免去了申请高门槛微信商户资质的繁琐周期，而且把开发量骤降了 60%！
```

### 每日关键推进动作拆解

1. **第 1~2 天（骨架搭设与资质前置）：**
   - 采购阿里云轻量服务器与域名，**立即启动域名 ICP 备案与公安备案手续**（绝对不等待代码写完才备案！）；
   - 设计关系型数据库核心表结构（用户表、渠道关系表、摄影作品表、预约记录表、佣金流水表）。
2. **第 3 天（前后台双轨推进）：**
   - 后台管理（登录、角色权限、渠道管理）与小程序端（首页轮播、作品瀑布流、预约表单）同步启动，编写完一个 API 立即联调一个前台页面。
3. **第 4 天（跑通核心主业务流）：**
   - 顾客扫渠道码 $\rightarrow$ 自动带入渠道 ID 绑定 $\rightarrow$ 提交预约 $\rightarrow$ 门店后台弹出待处理 $\rightarrow$ 门店核销录入消费额 $\rightarrow$ 渠道后台实时看到计佣增加，整条主链路彻底跑通。
4. **第 5~6 天（体验细节与健壮性补强）：**
   - 补全客片点赞、收藏、用户个人中心、渠道数据 Excel 一键导出，处理空状态与网络错误重试逻辑。
5. **第 7 天（三视角全场景严格自测）：**
   - **顾客视角**：从微信扫码授权、浏览作品、提交预约、查看预约进度完整走一遍；
   - **门店视角**：后台接单、核销录入、修改作品、导出财务报表；
   - **渠道视角**：换用两个不同渠道人员的账号登录，确认数据严格逻辑隔离，A 渠道绝看不到 B 渠道的客户与流水。
6. **第 8 天（真机排雷与 OSS 云存储）：**
   - 将作品样片迁移至阿里云 OSS，配置图片压缩缩略图规则；在真实 iPhone 和 Android 真机上测试页面加载耗时与排版。
7. **第 9 天（合规与隐私指引配置）：**
   - 让 AI 结合实际功能逐项生成微信官方要求的《小程序用户隐私保护指引》，填写申请读取相册、保存图片的合规原因。
8. **第 10 天（微信代码提审与正式交付）：**
   - 提交微信官方审核，3 小时顺利过审，正式发布上线，较约定合同期提前 4 天交付！

## 五、 关键排坑复盘：资深工程师的新手警示

### 1. 坑一：电脑开发者工具上能跑，真机上彻底白屏/报错

- **现象**：在微信开发者工具中由于勾选了“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”，所有网络请求都很正常；一到手机真机预览，页面直接报错卡死。
- **排查原因**：
  - 手机和电脑的网络环境不一致（开发者工具连的是本地 localhost 或内网 IP，手机无法直连）；
  - 域名的 SSL 证书不完整（缺少中级证书），PC 浏览器信任但手机微信底层不信任。
- **解法**：本地开发期必须在微信小程序管理后台把生产 API 域名加进 `request 合法域名` 白名单，并用手机热点配合真机调试。

### 2. 坑二：ICP 备案必须第一天启动，绝不能串行排队

- **血泪教训**：代码开发只需要 4~5 天，但域名购买后进行管局 ICP 备案通常需要 5~10 个工作日。
- **解法**：需求敲定的当天下午，第一件事就是让客户提供营业执照和法人人脸核验，立刻提交备案审核；**让备案时间与写代码时间完全重叠**，代码写完时备案刚好批复。

### 3. 坑三：微信隐私协议审核“多申请一项就可能被拒”

- **教训**：很多开发者为了省事，在后台把定位、麦克风、剪贴板等权限全勾上。微信审核团队会核查代码里是否真正使用了这些接口，一旦发现声明与实际不符，直接拒审打回。
- **解法**：严格按照代码调用的 API 申报权限，让 AI 输出严密的业务说明：“*读取相册权限用于用户保存摄影样片到本地手机相册*”。

### 4. 坑四：如何优雅拒绝客户的“顺便加一下”

在项目进行到第 5 天时，客户常会提出：“能不能顺便加一个客户评价打分功能？能不能顺便加一个多店切换？”
- **失控后果**：一旦口头答应，AI 会越改越乱，原定时间表彻底崩溃。
- **架构师应对话术**：
  > “李总，这个评价功能确实对品牌很有价值！不过由于它涉及到后台反垃圾审核和信誉积分算法，如果硬塞进本次 10 天上线的排期里，可能会影响整体系统的稳定性。我已经帮您把这个需求详细记入**《二期功能规划备忘录》**中，等这周我们先把核心的预约和渠道佣金跑通上线后，下周我们专门立项二期来加，您看这样好吗？”
