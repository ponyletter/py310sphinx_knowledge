# 购物车合并结算、买家定制信息表单与售后闭环

在承接多件商品批发采购以及个性化定制服务时，**购物车合并支付机制**与**结构化买家信息收集**是电商体验的关键分水岭。

---

## 1. 购物车与合并结算架构 (`Checkout`)

当买家加购多款不同商品时，如果要求买家逐件单独跳转网关支付，跳失率极高。24goods 实现了**“单次网关支付，多张子订单并行独立履约”**的合并结算模型：

```
买家购物车 (3 件商品)
   │
   ▼ POST /api/v1/checkout
生成单个合并结算单: Checkout (checkout_no: "C8A2K9L4M1Q3", amount: 153.20)
   ├── Order 1 (order_no: "G111...", 金额: 50.00, 自动发卡, 独立AccessCode)
   ├── Order 2 (order_no: "G222...", 金额: 80.00, 人工交付, 独立AccessCode)
   └── Order 3 (order_no: "G333...", 金额: 23.20, 自动发卡, 独立AccessCode)
   │
   ▼ 调用支付网关 (out_trade_no = "C8A2K9L4M1Q3")
网关扣款 153.20 元成功，回调触发一次性原子结算：
   ├── 标记 Checkout 为 paid
   └── 依次标记 Order 1, Order 2, Order 3 为 paid，各自入队独立发卡出库！
```

### 关键业务约束：
- **一致性总金额校验**：
  $$\text{Checkout.amount\_minor} == \sum \text{Order.amount\_minor}$$
  在数据库中严格校验，两者若出现任何一分钱分歧，整个事务立即回滚抛出 `InvalidState`；
- **独立售后与访问凭证**：每个子订单拥有独立唯一的 `order_no` 和提取凭证 `access_code`。买家日后针对其中某一件商品申请退款或换货时，不会影响其他正常交付的商品。

---

## 2. 数字化定制服务：买家凭据动态收集表单 (`BuyerInputSheet`)

针对需要买家提供个性化账号信息（如代充邮箱、游戏账号、服务器 IP 等）的非标服务商品，系统提供了轻量灵活的动态信息收集机制。

### 2.1 商品层级元数据配置
商家在后台编辑商品时，可勾选启用“买家定制信息”，配置如下结构化 JSON：

```json
{
  "enabled": true,
  "required": true,
  "label_i18n": {
    "en": "Your OpenAI Account Email & Temporary Password",
    "zh-CN": "需要代充值的 OpenAI 账号邮箱与临时密码"
  },
  "placeholder_i18n": {
    "en": "e.g. user@example.com / password123",
    "zh-CN": "例如：abc@gmail.com / 临时密码"
  },
  "multiline": true
}
```

### 2.2 前端无缝弹出与客服收件箱联动
- **拦截弹窗**：在商品详情页点击“立即购买”或在购物车结算时，若检测到商品需要定制信息且买家尚未填写，前端优雅弹出 `<BuyerInputSheet>` 底部抽屉让买家录入；
- **自动转交客服**：订单生成并完成付款后，买家填写的凭据自动作为一条系统文本消息同步推送到买家与客服的即时会话流中，并触发后台 CS Inbox 的声音提示与红点通知，客服可一键复制并立即着手代充交付；
- **安全加固 (Issue #8)**：由于定制信息可能包含敏感凭据，系统禁止将该字段记录在普通 Access Log 中，并在订单完成后配置定时任务定期清理脱敏。

## 3. 工单化售后闭环体系 (`AfterSales`)

交付后出现问题（例如卡密无效、账号被封）是虚拟电商不可避免的环节。

系统内置了标准化的售后生命周期流转：

```{mermaid}
stateDiagram-v2
    [*] --> 交付完成: 自动发卡 / 人工交付
    交付完成 --> 自动完结: 超出售后时效 (如72小时无异议)
    交付完成 --> 申请售后: 买家在订单详情页提交凭证工单

    state 申请售后 {
        [*] --> 待审核
        待审核 --> 驳回工单: 客服核实买家误操作 (填写驳回原因)
        待审核 --> 极速换货: 客服确认卡密损坏，从库中一键重新补发
        待审核 --> 原路退款: 客服同意全额/差额退款
    }

    极速换货 --> 交付完成: 换发全新卡密
    原路退款 --> 订单已退款: 触发复式记账账本原路冲正流水
    驳回工单 --> 交付完成
    自动完结 --> [*]
    订单已退款 --> [*]
```

### 核心亮点：
1. **自动完结倒计时**：发卡完成后开启保护时钟（默认 24~72 小时）。时钟归零后，订单自动流转为 `completed`，保障商家的资金结转确定性；
2. **复式记账原路冲正**：退款时，系统严格执行原收款明细的逆向反转记账，分销商佣金扣回，账面平稳无坏账。
