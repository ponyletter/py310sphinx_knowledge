# 08 昵称、头像、角标与 OCR 证据

客户身份匹配综合唯一昵称别名、头像指纹和置信度。多个客户共享昵称时需要头像区分；默认头像并不独特；疑似改名应转审核。姓名模糊相似只能作为候选，不能直接证明身份相同。

头像区域可能与红点重叠。代码会将重叠角标区域中和，再计算头像特征，否则同一个人仅因出现红点就可能被当成换头像。红色区域也不能单独证明角标，还要检测数字笔画，避免把红色头像当成未读。

## 本地 OCR 的三种读取模式

`line` 读取姓名、预览等单行；`block:` 读取可能换行的输入框或安全提示；`bubble:` 对文字气泡先分行，再读取并保留完整文本。不能只验证第一行就发送多行草稿。

低置信度交叉检查有真实计算成本。若检测器把小裁剪放大为多百万像素输入，几十个字段的首次读取就可能耗时数秒。不能为了快而直接接受更低置信度的文本；应该测量回退次数、输入尺寸、耗时和结果一致性。

案例短气泡曾被头像高亮拉长，中文换行也曾使块 OCR 插入额外字符，导致“可能已发送”。修复围绕气泡分割、逐行读取和精确草稿复核，而不是删除目标或发送检查。

**练习**：准备脱敏合成气泡，包含“您好”、多行文字、标点、相邻头像与失败感叹号，分别对比 line／block／bubble。测试输出保留断言，不把客户原文或截图写入公开报告。
