# 07 像素坐标、桌面隔离和校准生命周期

截图来自指定 X 显示上的可见像素。若该显示中的 Chrome 被其他网页或窗口盖住，OCR 看到的就是遮挡后的内容。RDP 窗口不需要在 Windows 前台常驻，但远端 Xvnc 会话、Chrome 和 worker 必须持续运行，且监控显示不能被其他界面遮挡。

## 三种不同的尺寸

远端 framebuffer、Chrome 的窗口／页面尺寸、Windows RDP 客户端缩放互相独立。本地“自动缩放”只改变观看方式；若 RDP 启用动态分辨率并真的修改了远端尺寸，则旧坐标失效。1280×1440 的宽高比为 8:9，不是竖屏 9:16。

|校准对象|案例快照|为什么需要|
|---|---|---|
|frame|1280×1440，16 位色深|先拒绝错误桌面或错误尺寸|
|row|18 行，行高 68|逐行读取与目标定位|
|title|会话标题区域|确认点击的是目标客户|
|message_pane|650×272 的最近消息区域|控制回复核验成本|
|composer|输入框文字区域与点击点|空草稿、粘贴内容复核|
|image dialog|标题、完整路径、Open 按钮|确认文件选择的不可逆动作|
|anchors|页面标志和列表标题摘要|布局不正常时停止输入|

## 分辨率增大带来的收益和成本

高度翻倍能展示更多客户和上下文，但不等于代码会自动利用全部上下文。案例采用大列表＋较短的最近消息核验区；完整聊天区域留作未来上下文采集设计。把 pane 无限变大，会增加气泡分割、OCR 和模板匹配成本。

变更流程：暂停回复 → 保留旧配置 → 调整显示／Chrome → 截图确认实际尺寸 → 重标行、区域、颜色和对话框 → 重新取锚点 → 离线回放 → 受控发送 → 恢复。锚点报错不是应随意放宽阈值的提示。

**练习**：分别记录 1280×720 和 1280×1440 的可见行数、采集耗时及首次分析耗时；保持色深和缩放一致。不要把 RDP 观看窗口尺寸当作远端截图尺寸。
