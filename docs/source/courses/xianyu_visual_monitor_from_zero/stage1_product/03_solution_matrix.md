# 03 视觉方案与 API、DOM、RPA、视觉模型的比较

## 为什么这个项目选择截图和本地 OCR

它读取已经登录的屏幕，不依赖聊天网页 DOM 层级，也不需要向另一进程导出 Cookie。识别过程可以离线回放；同一套截图、区域校准、任务状态机还能迁移到其他网页或桌面软件。这些是工程上的优势，不代表账号操作天然获得平台授权，或不会被界面变化影响。

|路径|适用条件|优势|代价与本项目选择|
|---|---|---|---|
|平台官方 API|平台确有接口且账号已获授权|结构化 ID、事件及错误码|优先评估；本课程没有假定闲鱼已开放所需聊天接口|
|DOM／浏览器自动化|明确获准且网页结构可控|定位精确、易读取完整可访问文本|本项目运行时明确不采用，避免混入两套证据来源|
|截图＋本地 OCR＋确定性规则|只能读取现有界面、隐私优先|可回放、跨 Web／桌面、成本可测|前台像素依赖、校准和首次 OCR 成本|
|通用 RPA|流程稳定、动作范围明确|低代码编排较快|复杂异常状态仍需持久化与发送核验|
|视觉大模型代理|语义复杂、变化大、容忍更高延迟|能解释丰富场景|输出不确定、成本和数据边界；不能直接替代发送校验|
|混合系统|分工和证据边界清楚|规则处理常见路径，模型辅助草稿|推荐作为未来方向，而不是当前已实现功能|

本项目不是“完全不受页面改版影响”：颜色、字体、位置、分辨率、滚动状态都会改变识别条件。独立桌面解决前台被其他窗口遮挡的问题，却不解决登录过期、网络断开和不可见历史。

## 选型记录应该包含什么

按“输入能否取得 → 身份是否稳定 → 操作如何确认 → 失败如何恢复 → 单次耗时 → 维护责任”六项评分，给每个候选方案设计同一个测试场景。对比不能只拿 OCR 的最快缓存值去比较 API 的端到端耗时。

**练习与交付**：选一个自有后台，在读取条件允许的前提下分别设计官方接口适配和像素适配，说明两者共用哪些任务、审计和规则模块。不要将对比设计用于调用未经授权的私有接口。
