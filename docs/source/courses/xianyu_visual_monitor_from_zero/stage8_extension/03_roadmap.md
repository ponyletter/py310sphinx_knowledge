# 24 从工程原型到可维护产品

## 回看这条真实演进路径

最初完成可见行监测和邮件；随后补上“第一次手机读过、以后新来信仍应提醒”。自动回复又暴露草稿核验、失败图标、连续来信、保持选中导致自动已读、上传延迟和 GTK 回车取消等问题。每次改动都应落在状态和证据上，而不只是多加一次 sleep。

独立虚拟桌面把日常浏览与自动化隔离；1280×1440 增加可见范围；精确缓存、A76 绑核与匹配器减少重复计算；PR26 又说明基准工具本身也要审查，不能只看一个 identical 布尔值。

## 产品交付应包含什么

版本清单与许可证、无秘密的配置模板、私密部署说明、基线定义、规则清单、启动停止命令、受控收讫记录、性能报告、备份恢复演练、已知问题、人工接管和售后边界。

源码采用 MIT，分发源码片段和派生物应保留许可证声明。本课程附带从指定 commit 冻结的核心文件，来源和哈希在附录，可用于教学对照；这些文件不会代替生产安装。

## 结课项目

给一个新卖家制作部署方案、报价和验收计划，在隔离测试环境复现首次提醒、连续来信和图文回复；提交一份“已验证／未覆盖／未来设计”的交付报告。只有能解释不确定状态和恢复路径，才算完成从 0 到 1。
