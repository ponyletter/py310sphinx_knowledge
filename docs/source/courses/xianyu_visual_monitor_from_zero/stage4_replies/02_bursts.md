# 11 连续来信、过时任务与草稿保护

早期出现过：任务触发文本是“您好”，进入会话后最新气泡已变成“还在吗”，程序安全取消，却在界面显示为失败。正确处理不是取消最新气泡检查，而是让排队中的旧意图在输入前被新来信替换。

`reply_debounce_seconds` 给短时间连续来信一个合并窗口。它依据最后**观察到**的输入规划，不保证恢复截图间隔中未看到的每一条。较新问题没有匹配规则或需要审核，也应取消尚未输入的旧自动回复。

|新消息到达时机|处理|
|---|---|
|排队或目标核实阶段|旧任务 superseded，重新规划|
|已粘贴、尚未回车|不回车，保留草稿并暂停供人检查|
|已回车|保留已提交事实，核实结果，不能当作从未发送|
|图片选择前|复核已核实文字和目标，变化则取消图片|
|图片上传核实中|持续读取可见新上下文，结果保持分离|

最新气泡检查到真正回车之间仍有很小的输入竞态，像素系统无法把远端平台变成原子事务。应在已知问题中说明，不用“已经 debounce”掩盖这个边界。

**练习**：用合成帧重放 A→B 连续消息，断言 A 不会被当作失败后自动重试；再测试已粘贴时 B 到达，确认不会覆盖用户草稿。
