# 04 架构分层：Web 管理面与桌面执行面

![采集、分析、决策和执行之间的数据流](../_assets/pipeline.svg)

|目录|职责|不应承担的职责|
|---|---|---|
|`capture/`|X 显示发现，scrot／command／replay 截图|解释客户语义|
|`vision/`|区域校准、颜色与气泡、布局锚点、图片匹配|直接提交业务回复|
|`ocr/`|本地引擎、进程池、精确像素缓存|判断账号身份|
|`detection/`|昵称归一化、头像证据、逐客户状态变化|仅凭总未读数生成事件|
|`replies/`|规则、回复意图、目标核验、文字和图片输入|把不确定发送变成自动重试|
|`queueing/`|数据库任务箱、租约、有界内存队列|用内存代替持久化|
|`worker/`|协调采集、分析、任务派发及桌面互斥|允许同桌面多个输入执行器|
|`web/`|管理 UI、审核、配置和诊断|自己截图、OCR 或模拟键盘|

Web 可以有多个 HTTP worker；每个桌面只能有一个采集／输入 worker。这里“worker”一词有不同层级：uvicorn HTTP 进程、应用桌面 worker 和 OCR 子进程，不能混为一谈。

## 一条消息的路径

1. 截图携带采集时间，经过有界队列。
2. 分析器先验证画面尺寸和锚点，再比较各行像素。
3. 业务事务做客户身份归并、状态转换、事件去重。
4. 同一事务写入提醒任务或回复意图，执行进程稍后领取。
5. 输入前后重新截图核验，结果写回 MySQL。
6. F5 返回有自己的结果，不能覆盖发送结果。

代码入口是 `cli.build_worker` 与 `worker/service.py`，而不是模板页面。精确源码入口和冻结版本见[源码附录](../appendix/02_source_map.md)。
