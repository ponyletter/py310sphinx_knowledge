# 05 四类状态与“首次无红点”的补提醒

## 不要只保存“最后一条文字”

需要分别保存客户身份、最近可见状态、消息事件、发送任务。`RowState` 包含预览、角标、角标像素摘要、时间、位置、修订号和状态摘要。预览相同不代表没有新消息：用户可以连续发送两个“你好”。

|变化|事件|原因|
|---|---|---|
|角标出现或数字增加|incoming|可见来信证据|
|角标消失且预览不变|read_elsewhere|可能在手机读过，不应再次发邮件|
|预览变化但没有角标|possible，或由聊天气泡方向补证|也可能是自己发出的消息|
|相对时间自然老化|不生成来信|“刚刚”变“一分钟前”是时间流逝|
|同文本、角标增加|incoming|重复文本也是新来信|

## 客户生命周期与首次通知资格是两件事

早期错误是“第一次发现无红点 → 创建客户 → 后续认为不是新客户 → 永远不建首次通知”。修复思路是：客户已存在不等于首次提醒已完成。后续出现可靠 incoming 时，仍检查该客户是否符合首次通知条件、是否已有唯一提醒任务。

提醒任务使用 `new_customer:<customer_id>` 一类持久化去重键，数据库唯一索引保证反复处理或重启不会重复建任务。不要把唯一性只放在 Python 的 `set()` 里。

## 可重复的验收步骤

在隔离验收库中，测试账号发“甲”，卖家手机读完，随后首次采样：无红点、不发提醒；再发“乙”且卖家不读：建立唯一首次任务；再发“丙”及重启：仍只有一个；最后手机读完：红点消失不算来信。

不要为了制造“新客户”删除生产客户或清空生产库。上述场景验证的是“启用后首次被发现、且不在历史基线”的业务口径，不是平台上的绝对新用户。
