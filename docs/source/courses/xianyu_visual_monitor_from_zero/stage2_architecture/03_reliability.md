# 06 持久化任务箱、租约与不可逆边界

## 先记意图，再做动作

数据库事务提交任务不等于任务已经发送。队列状态为 `pending → leased → succeeded / failed / uncertain / cancelled`；每次尝试另记阶段与错误。连接失败可以重试，发送过程已经提交后失联则不应盲目重试。

|边界|可证明什么|恢复原则|
|---|---|---|
|SMTP 尚未提交 DATA|通常尚未投递正文|根据错误类型重试|
|SMTP 已进入 submitting 后断线|可能已被服务器接收|标记 uncertain，人工查收后决定|
|回复尚未 typing|没有粘贴和回车|较新来信可取消旧意图|
|已粘贴但未发送|存在草稿|保留草稿并暂停，不能套用无输入重试|
|已回车、未核实|可能发送成功|查接收端；不可自动重发|
|图片 Open 已点击|可能已有上传在进行|等待并核验，不能再次选择文件试运气|

## 两道并发保护

主机文件锁阻止同主机重复启动，MySQL 的 `worker_leases` 再提供租约保护。服务失去租约应停止执行。内存帧队列和任务队列有上限，压力大时产生背压并记录队列统计，不静默吞掉任务。

桌面动作还需要互斥锁：采集可以排队，但不能让两个执行器交替点击、粘贴、回车。帧时间水位会把动作前排队的旧截图标为 superseded，避免旧画面覆盖刚完成的状态。

**练习**：分别模拟“任务入库前崩溃”“入库后领取前崩溃”“已 typing 后崩溃”。写明哪些状态可恢复、哪些必须先看接收端，而不是给所有异常套统一重试。
